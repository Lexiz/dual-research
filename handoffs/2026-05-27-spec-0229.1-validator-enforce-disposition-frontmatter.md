# Spec 0229.1 — Validator: enforce `disposition:` + `disposition_reason:` frontmatter

Deployed to https://dual-research-alex.fly.dev/ — `/api/health` returns `{"ok":true,"version":"1.49.0","backend":"supabase"}`.

## What landed

- **`scripts/spec_lifecycle/validator.py` — new gate.** A module-level `VALID_DISPOSITIONS = {"ship", "defer", "archive"}` constant sits adjacent to `VALID_TYPES` / `VALID_STATUSES`. Both `DEV_REQUIRED_FRONTMATTER` and `DRAFT_REQUIRED_FRONTMATTER` now include `disposition` + `disposition_reason`, so absence is reported via the existing missing-keys check (one error per missing key). A new `_check_disposition_shape(fm, errors, warnings)` helper layers value-shape gating on top: invalid values produce an error naming the valid set, empty / non-string reasons produce a "non-empty single-sentence" error, and reasons with more than two periods warn (rather than error) per the spec's R2 single-sentence heuristic. Both `validate_dev_spec` and `validate_draft` call the shared helper, so the gate fires identically at draft time and queue time.
- **`scripts/spec_lifecycle/backfill_disposition.py` — new one-off CLI.** Text-level insertion (avoids yaml round-trip churn) of `disposition: archive` + the canonical retroactive reason between the frontmatter and the closing `---` of every spec/draft that doesn't already carry the field. Scope: `specs/*.md` (top level) + `specs/drafts/*.md`. Explicitly excludes `specs/_templates/` and `specs/archive/` per spec §5. Idempotent — files with frontmatter already containing `disposition` are skipped. First-pass output: `backfilled 235 files (6 skipped — already had disposition)`. The post-merge follow-up commit (#270) picked up one further spec (0232, queued mid-flight) with `backfilled 1 files (241 skipped)`.
- **235 spec + draft files backfilled (PR #269) and one more in PR #270.** Every existing `specs/NNNN-*.md`, `specs/NNNN.M-*.md`, and `specs/drafts/draft-*.md` now declares `disposition: archive` + `disposition_reason: "Pre-spec-0229 carve-out; disposition assigned retroactively to satisfy the new convention."`. The blanket-`archive` choice is intentional per spec §2.3 — these specs predate the convention so triage can't be reconstructed; `archive` preserves queue-state semantics (`/dev-next` will filter on `disposition: ship` going forward, so the historic queue is naturally left alone).
- **`CHANGELOG.md` + version bump → 1.49.0.** `## [1.49.0] — 2026-05-27` section directly under `## [Unreleased]`, single `### Added` bullet citing this spec. `pyproject.toml`, `src/dual_research/__init__.py`, `uv.lock`, and `src/dual_research/ui/static/version-notes.json` (regenerated via `scripts/build_version_notes.py`) all moved to 1.49.0 in lockstep.
- **Tests at [`tests/test_spec_0229_1_validator_disposition.py`](tests/test_spec_0229_1_validator_disposition.py) (new, 11 tests).** Unit coverage for: dev-spec missing disposition (errors include the literal word "disposition"); dev-spec invalid value (errors name `'ship'`, `'defer'`, `'archive'`); dev-spec happy path (passes); empty reason (errors on "non-empty"); multi-sentence reason (warns, doesn't fail); draft missing disposition (parallel error); draft happy path; source-pattern lock-in for the `VALID_DISPOSITIONS` constant + the runtime `VALID_DISPOSITIONS == {"ship", "defer", "archive"}` set check; backfill idempotency across two subprocess runs; in-repo invariant that no canonical-named spec/draft fails on disposition-class errors post-backfill; CHANGELOG/version smoke. Fixture updates in [`tests/spec_lifecycle/test_validator.py`](tests/spec_lifecycle/test_validator.py) and [`tests/spec_lifecycle/test_depends_on_frontmatter.py`](tests/spec_lifecycle/test_validator.py) added the new required fields so the older suites stay green.

## Deferred during implementation

- **Update the `/dev-next` skill to filter the queue head on `disposition: ship`.** Per spec §5 — the validator + backfill landed here; the skill change is the natural follow-up. The skill SKILL.md lives at `~/.claude/skills/dev-next/SKILL.md` (out-of-repo, not under spec governance). Until the skill change ships, every backfilled-as-`archive` spec is still picked by `current_queue()` and the queue-head consumer doesn't yet honour the field — which is benign because the only backfilled-as-`archive` specs that are still `status: queued` will be picked as today; the doctrine is just that they shouldn't be. Pointer: `~/.claude/skills/dev-next/SKILL.md`. The change is small (filter on `disposition == "ship"` after `current_queue()`).
- **Update `/spec-queue`, `/spec-promote`, `/spec-draft` skills to prompt for `disposition` interactively.** Same out-of-repo class — the validator currently catches omissions with a hard error, but the UX could ask up-front instead of after-the-fact. Pointers: `~/.claude/skills/spec-queue/SKILL.md`, `~/.claude/skills/spec-promote/SKILL.md`, `~/.claude/skills/spec-draft/SKILL.md`.
- **Update `specs/_templates/*.md` to include `disposition:` placeholders.** Per spec §5 — five templates (`new-feature.md`, `bug.md`, `refactoring.md`, `test.md`, `breaking.md`) all lack the field. Authors who use the template verbatim get a clear validator error, but the better UX is to ship the placeholder. Best done as a `refactoring` spec that touches all five in one pass. File pointers: `specs/_templates/new-feature.md` etc.
- **Relax the spec §3 acceptance criterion's "every existing spec validates green" claim, or close the gap.** Spec §3 says "`uv run python -m scripts.spec_lifecycle.validator specs/<any-existing-spec>.md` returns 0 post-backfill — every existing spec carries `disposition: archive` + a reason and the validator passes." That is overstated — 236 dev specs fail the full validator today (and have failed for months) on rules that landed after they were queued: citation-count, source-traceability tables, UI-test path conventions, etc. The spec 0229.1 contribution is "no disposition-class failure," which `test_no_existing_spec_fails_specifically_on_disposition` asserts. Two paths forward: (a) accept the validator-evolution debt and amend §3 in a `refactoring` spec; (b) author a `refactoring` spec that walks the historical corpus and brings each old spec into compliance with current rules. Path (a) is materially cheaper; path (b) is the structurally cleaner long-term posture but is large.
- **Backfill `disposition_reason` text is mildly misleading for post-0229 specs (e.g., 0232).** The deterministic backfill stamps every retroactive entry with `"Pre-spec-0229 carve-out; disposition assigned retroactively to satisfy the new convention."`, including for specs queued after 0229 itself (the PR #270 case). The disposition value (`archive`) is structurally correct — 0232 was queued without triage intent — but the literal "Pre-spec-0229" phrasing isn't accurate for those specs. Two options: (a) keep one-line marker (cheap, semantically OK, slightly inaccurate) or (b) split the script into two paths — pre-0229 vs post-0229 — with different default reasons. Deferred; the disposition field's value is the operational lever, not the reason text.
- **Dashboard renderer does not surface `disposition`.** Spec §7 R3 noted that backfilled-as-`archive` specs may clutter the dashboard queue view. The renderer at [`scripts/spec_lifecycle/render_dashboard.py`](scripts/spec_lifecycle/render_dashboard.py) doesn't currently read or render the field. Surfacing it (as a column, a filter, or a per-card chip) is a separate UI spec.
