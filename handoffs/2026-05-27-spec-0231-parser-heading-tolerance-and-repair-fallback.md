# Spec 0231 — Parser heading tolerance and graceful repair fallback

Deployed to https://dual-research-alex.fly.dev/ — root returns the dashboard HTML (`/healthz` is not an endpoint on this app; live-fetch smoke confirms the new version is serving).

## What landed

- **Layer §2.1 — `_normalise_section_heading` strips a leading `## ` token.** [`src/dual_research/protocol/parse.py:650`](src/dual_research/protocol/parse.py:650) gains a pre-pass `re.sub(r"^##\s+", "", h)` before the existing numeric-prefix strip. The drafter's inline-anchor pattern `### EDIT_SECTION ## 1. Summary` now normalises to `summary` and binds against the prior draft's `## 1. Summary` section. Standalone-anchor form (`### EDIT_SECTION 1. Summary`) normalises identically — back-compat preserved.
- **Layer §2.2 — `extract_fenced_section` accepts glued `## <heading><prose>`.** [`src/dual_research/protocol/parse.py:179`](src/dual_research/protocol/parse.py:179) replaces the trailing `\s*$` end-anchor with `(?:\s*$|(?=\S))` — either end-of-line (clean form) OR a non-whitespace character lookahead (glued form). Anchor-fixture pattern `## New items I'm raisingNow I have evidence...` now recovers a body containing all six `### RAISE` blocks. The body remains bounded by the next `^##` heading outside fenced ranges, so downstream finders (`### RAISE`, `### ADDRESS`) still locate their op blocks correctly. Partial-prefix false-matches are blocked by the lookahead — `## New items I'm raising` does NOT match heading `"New items"` because the next char after "items" is whitespace, not end-of-line and not the start of glued prose.
- **Layer §2.3 — graceful drafter-side no-op fallback + mandatory `ProtocolViolation`.** `_on_revised_draft` extracted to module-level [`_apply_drafter_revised_draft`](src/dual_research/orchestrator/dr_run.py) for testability. On `ProtocolParseError` from `extract_revised_draft_deltas`, the helper synthesises a `RevisedDraftFull(content=prior_draft)` payload — the prior draft body verbatim, NOT the unparseable original (which would ship `ANCHOR:` / `REPLACE_WITH:`-shaped garbage downstream) — applies byte-equal, and emits `ProtocolViolation(violation_code="phase4_drafter_repair_failed", op_kind="revised_draft")` so the deadlock is observable. [`parse_v2_with_repair`](src/dual_research/orchestrator/repair.py) at the `failures >= 2` site gains a drafter-only exemption: drafter persistence past 2 consecutive failures no longer raises (the fallback handles it downstream and the run continues to `hard_cap`); reviewer keeps the exit-52 path unchanged.
- **`ProtocolViolation` docstring** at [`src/dual_research/events/types.py:503`](src/dual_research/events/types.py:503) gains a 10th `violation_code` entry — `phase4_drafter_repair_failed` — with the implementer caution (frequent firing signals layers §2.1/§2.2 are too narrow; the fallback is a last-resort safety net, not the de-facto fix).

## Cycle notes

- **Anchor-fixture replay was the load-bearing assertion.** The two integration tests that replay the actual phase-2 and phase-4 turns from `tests/fixtures/anchor-runs/20260527-054652-backend-language-choice/` are what prove the fix lands the failure. The synthetic parser-unit tests catch shape regressions, but the fixture replays catch "did we fix THE bug" — they hard-fail on `main` (pre-fix `extract_revised_draft_deltas` raises and `extract_fenced_section` returns `None`) and pass post-fix with `>= 10 EditSectionOps` and `== 6 RAISE blocks`.
- **`_on_revised_draft` refactor to free function.** The closure form was untestable (uses `nonlocal revisions_count` + enclosing `drafter`). Module-level `_apply_drafter_revised_draft` takes everything as kwargs and returns `True` / `False` to signal whether a revision was written; the closure wraps it and updates `revisions_count` on `True`. The integration test imports the helper directly and exercises the byte-equal no-op + PV emission without needing to stand up a full `run_dr_phase4` invocation.
- **Drafter exemption from exit-52 was a deliberate choice over a reset-consecutive variant.** Two options for keeping the run alive past persistent drafter parse failures: (a) reset `consecutive_failures` to 0 at `parse_v2_with_repair` line 392 (second-call validator failure), or (b) suppress the `failures >= 2` raise at line 326 for drafter only. (a) only buys one extra round before exit-52; (b) lets the run continue indefinitely until `hard_cap` catches the deadlock — which is exactly what spec §2.3b calls for ("the existing hard-cap catches a legible deadlock instead of an opaque exit-52"). Reviewer still raises because reviewer has no fallback. The per-round `ProtocolViolation(phase4_drafter_repair_failed)` makes each occurrence observable on the dashboard, so a stuck drafter is loud, not silent.
- **PR diff excluded local queue-state.json modifications.** The `--push-to-main` plumbing wrote events to `origin/main` directly during the cycle; local queue-state.json drifted ahead of branch HEAD. Staging it in the PR would have re-added events that are already on main, producing duplicates on squash-merge. The commit `fee878e` stages everything else; queue-state.json is touched only via the post-deploy atomic `push-files-to-main` at step 23.
- **Cycle-start anchor events lost on dashboard.** Steps 1, 8, 9, 11 (`cycle_started` / `preflight_ok` / `handoff_read` / `spec_read` / `planning_started` / `reconcile_complete`) were emitted via `append-event` *without* `--push-to-main` and never made it to `origin/main` — the first `--push-to-main` call at step 12 syncs local from remote first, overwriting the buffered events. The skill's step-12 commentary mentions a "later flush" path, but the queue_state CLI has no flush command. Spec follow-up worth filing: either change `append-event` to always `--push-to-main` for these anchor steps, or add an explicit `flush` subcommand the skill calls at step 12. Filed below.
- **No deploy flake this cycle.** GH Actions [run 26513517308](https://github.com/Lexiz/dual-research/actions/runs/26513517308) ran clean — test job 39s, deploy job 50s, single push. The `Failed to save / Failed to restore` cache annotations are GH-side ephemeral; unrelated to the fly deploy.
