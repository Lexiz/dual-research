Where the app still bypasses its own design system

Specs 0127–0134 introduced Design System v2 — a Material 3 vocabulary, token-only colors, and a canonical component catalog. This audit walks every visual element across all 19 JSX modules and surfaces every place the live UI still drifts from the prescribed system. Page chrome below is built from DS v2 tokens; if a row's Found column looks off, that's intentional — it's the deviation reproduced faithfully.

01

Colors & palettes

3 deviations

Three concentrated color bypasses. KIND_COLORS and SUBINPUT_COLORS are constant objects defining bespoke palettes that shadow the agent / status tokens entirely. The Google sign-in button uses Google's brand hex codes — a deliberate vendor lock-in that may be legitimate but should be expressed as a named token, not raw hex.

F-color-001

KIND_COLORS — bespoke status palette shadowing agent/status tokens

❌ Bespoke bypass

A module-level constant defines hex/rgba colors per turn-kind that should consume --agent-a, --agent-b, --ok, --warn, --err directly. The mixed approach (rgba bg + token fg) suggests the migration stalled mid-way.

02

Typography

~85 deviations

The biggest single category. The type scale defines display / headline / title / body / label at sm/md/lg sizes — but ~85 inline fontSize: <number> literals scatter across the app, some non-canonical (9, 9.5, 10.5, 11, 12.5, 13.5). Most are clustered in the two largest files. The DS-showcase page is itself the second worst offender, which undermines the demo's authority.

F-type-001

Inline fontSize: <number> instead of type-role tokens

⚠️ Token drift

Inline numeric fontSize bypasses the type scale. Some values (9, 10.5, 13.5) aren't on the scale at all — those need either rounding-to-grid or a documented exception.

03

Spacing

~75 deviations

Inline padding / margin / gap literals throughout. The token scale is --md-sp-1 (4px) … --md-sp-18 (72px) on a 4px grid. Most violations align to the grid by accident (8, 12, 16, 24); some don't (6, 10, 14) and either need a new half-step token or rounding.

F-space-001

Inline padding/margin/gap numerics instead of --md-sp-* tokens

⚠️ Token drift

Hardcoded pixel literals bypass the spacing scale entirely. Even grid-aligned values like padding: 16 should read padding: 'var(--md-sp-4)' so a future density-mode change propagates.

Interaction & motion

3 deviations

Where the app uses imperative JS to mutate styles on hover instead of the M3 state-layer pattern (a translucent overlay driven by CSS :hover / :focus-visible). This is the only category that needs a runtime check to fully catch — static audit can find the imperative patterns but can't compare easing/duration to the M3 motion spec. A Chrome-MCP pass on run-detail and search is recommended as follow-up.
