# Spec 0257.2 — raiser no-self-address prohibition on group-3 standing items

Shipped in **v1.66.2** (PR [#299](https://github.com/Lexiz/dual-research/pull/299),
deploy run [26703666150](https://github.com/Lexiz/dual-research/actions/runs/26703666150)
green; homepage smoke 200). Closes the lone residual phase-2 violation
class from spec 0257's live validation run (`raiser_self_address`).

## What landed

A prompt-text-only steering fix on the **live** standing-items surface.

- **`_RAISER_ADDRESSED_INSTRUCTION`** ([`src/dual_research/orchestrator/deep_research.py:176`](../src/dual_research/orchestrator/deep_research.py))
  — the group-3 ("Raised by you — ADDRESSED, ready for you to ratify")
  instruction — now carries the no-self-address prohibition, mirroring
  the group-2 wording (`_RAISER_OPEN_INSTRUCTION`). It explicitly states
  that `### ADDRESS <id>` on your own item is `raiser_self_address` and
  will be dropped, and that the item is already addressed so the raiser
  should ratify instead. The already-legal `### WITHDRAW` op
  (`addressed → withdrawn`, [`lifecycle.py:60`](../src/dual_research/contract/lifecycle.py))
  is now surfaced alongside the ratify ops.

## Root cause (recap)

When a raiser's item flips `open → addressed`, the renderer moves it from
group 2 to group 3 ([`deep_research.py:242-247`](../src/dual_research/orchestrator/deep_research.py)).
Group 2 carried the no-self-address prohibition; group 3 did not — so the
item **lost** the prohibition on the transition and the raiser reached for
`### ADDRESS` again. 5× in live run `20260530-205144-spec-0257-validation`
(phase 2, round 3, agent `claude`, items `D-plan-c-01`..`04`, `Q-plan-c-01`).
The ops were dropped and did **not** block convergence (all three phases
still reached `via_genuine_resolution`) — a non-blocking steering gap, not
a contract break. No code path, partition logic, verifier invariant,
lifecycle edge, or event type changed.
