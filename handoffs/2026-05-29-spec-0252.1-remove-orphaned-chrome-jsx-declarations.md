1. `flyctl deploy` → `Get "https://api.machines.dev/...": read: connection reset by peer`

The cycle halted at `failure_step=deploy` (the merge had already landed, so the code was safe on `main`). A **third** rerun of the same failed run succeeded once Fly recovered — `deploy` + blue-machine sweep both green, v1.63.1 now live. The queue-state `merged → failed → deployed` transition is recorded in the event sidecar.

**Lesson for the orchestrator:** the original watch step piped `gh run watch --exit-status` into `tail`, so `$?` captured `tail`'s exit code (always 0) instead of the watch's — masking the first failure. The skill's canonical form runs `gh run watch` un-piped for exactly this reason; do not add a pipe.
