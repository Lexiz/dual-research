# Spec 0257.1 — delete the dead legacy standing-items surface

Shipped in **v1.66.1** (PR [#298](https://github.com/Lexiz/dual-research/pull/298),
deploy run [26703432244](https://github.com/Lexiz/dual-research/actions/runs/26703432244)
green; homepage smoke 200). Dead-code removal — the carve-out flagged in
the [spec 0257 handoff](2026-05-30-spec-0257-phase2-role-aware-standing-items-addressee-obligation.md)
"Deferred during implementation" §1.

## What landed

The legacy ledger-mode standing-items prompt surface and its two
orchestrator runners — unreachable from the live entry points
(`run_dr_phase2` / `run_dr_phase4`, via `_drive_interaction_phase`)
since the spec-0118 v2 rewrite — are gone.

- **`ledger/prompt.py` deleted in full.** `build_standing_items_section`
  + its private helpers (`perspective_other`, `_them_label`,
  `_sort_key`, `_id_sort`, `_format_entry_line`) + `build_blocked_convergence_warning`.
  Re-exports dropped from `ledger/__init__.py` (`__all__` and the
  module docstring's public-surface list).
- **Legacy `orchestrator/phase2.py:run_phase2` and
  `orchestrator/phase4.py:run_phase4` deleted** — the only callers of
  the deleted prompt surface. Both files are now reduced to their
  preserved `Phase2Outcome` / `Phase4Outcome` dataclasses plus a module
  docstring.
- The live role-aware standing-items surface is unchanged:
  `deep_research.format_role_aware_standing_items`, rendered off the
  contract `LedgerEntryV2` state machine. Removing the second,
  diverging renderer disarms the wrong-layer trap that produced spec
  0257's reconcile-time citation bug.

## Scope decision — `build_blocked_convergence_warning` removed too

The spec's §3 Step 1 line-range stopped before this function (spec 0089
§C), but a call-graph read showed its **only** callers were the two
legacy runners being deleted (`phase2.py:187`, `phase4.py:188`). It
became unambiguously dead in the same pass. Leaving it would have
reduced `ledger/prompt.py` to a single dead function (re-arming a
smaller version of the same trap) and spawned a trivial follow-up — the
exact accretion pattern CLAUDE.md warns against. The spec's §4 already
mandated deleting its only test file (`tests/ledger/test_prompt.py`), so
removing the function with it is faithful to the spec's stated intent
(§1/§2: "the dead surface is gone"). Documented in the PR scope note.

## Preserve-list verification (live contract)

`Phase2Outcome` / `Phase4Outcome` kept **in place** — the spec's
"either keep them or relocate" option A (lower risk, no import-site
rewrites). Each of the three live import sites confirmed to still
resolve:

- `dr_run.py:79` / `:81`, `run.py:40` / `:42`, `finalize.py:8` / `:10`.

The alarming-looking `run.py:461`/`:493` `await run_phase2(...)` /
`await run_phase4(...)` call sites are **not** the legacy runners —
`run.py:32-36` imports `run_dr_phase2..4 as run_phase2..4`, so those
calls hit the live drivers. Only the `Phase*Outcome` dataclasses are
live-imported from the legacy modules. The captured anchor-run
traceback (`run.py:477 run_session → dr_run.py:1544 run_dr_phase4`)
corroborates the aliasing.

## Deferred during implementation

- **Delete the parallel dead `orchestrator/phase3.py:run_phase3` runner** —
  while removing the phase2/phase4 legacy runners I confirmed
  `orchestrator/phase3.py:run_phase3` ([`src/dual_research/orchestrator/phase3.py:29`](../src/dual_research/orchestrator/phase3.py))
  is the exact same dead-legacy-runner pattern: production `run.py:35`
  aliases `run_dr_phase3 as run_phase3` so the live call at `run.py:482`
  hits the live driver, and `phase3.py:66` carries the identical "Spec
  0118: legacy run_phase3 path no longer emits…" dead-path comment. Its
  only remaining callers are test-only
  ([`tests/orchestrator/test_phase3_4_final.py:104`](../tests/orchestrator/test_phase3_4_final.py),
  `:125`). It was **out of this spec's named scope** (0257.1 targeted the
  standing-items surface, which the single-drafter synthesis phase 3
  does not have), so it was deliberately not touched. A follow-up should
  delete `phase3.run_phase3` + its two test exercises, preserving the
  live `current_draft_path` and `Phase3Outcome` (both imported by
  `finalize.py` / `dr_run.py` / `run.py`). Mirrors this spec's shape
  exactly.
