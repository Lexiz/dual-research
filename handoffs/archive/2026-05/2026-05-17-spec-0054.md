## What shipped

Two new design-system primitives (QuestionThread and QuestionRef) plus AP-01 anti-pattern enforcement. QuestionThread is a vertical turn-by-turn conversation timeline with dashed-rail `::before` trick, agent-tinted pills with round + verdict, serif quote blocks, and drift/resolved footer banners. QuestionRef decodes legacy `Q-g-r1-04` database keys into legible chrome in compact (`Q . 04`) and full (`Q . 04 . [GPT] . r1`) formats. QuestionCard's expanded body now renders a full QuestionThread with turns derived from existing question fields; ghosted questions show drift status. CardHeadline for questions displays decoded number instead of raw DB key.

### Mid-flight refinements

- **D5/D6 (turns derivation)** -- the draft expected `run.questions[id].turns` to exist on the wire. It doesn't. Turns are derived in the frontend from flat question fields (raisedBy/raisedRound + answeredBy/answeredRound). This gives at most 2 turns (origin + answer) plus an optional ghosted marker. Multi-round threads would require wire-format changes in a future spec.
- **D7 (AP-01 sweep)** -- the draft expected Q-[cg]-r\d+-\d+ text spans rendered in run-detail.jsx and errors.jsx. Actual codebase has no such raw-text renders. The only cryptic ID exposure was in CardHeadline's `publicId={q.id}` which is now decoded. The how-it-works.jsx description string mentioning `Q-c-r1-01` is user-facing documentation (not cryptic chrome) and was left as-is.
- **D4 (QuestionRef agent mapping)** -- the brief uses `agent: 'a'|'b'` convention. This codebase uses `'claude'|'gpt'` for data and `'a'|'b'` for CSS classes. Added `_agentSlot()` mapping helper.
