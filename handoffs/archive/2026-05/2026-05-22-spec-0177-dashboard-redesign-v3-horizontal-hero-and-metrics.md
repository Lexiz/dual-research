# Spec 0177 — Dashboard redesign v3 — horizontal hero + timeline, populated Metrics tab, pagination, pastel charts, light default

v1.31.0 brings the spec dashboard in line with the [dashboard-redesign-v3-horizontal.html](../dashboard/mockups/dashboard-redesign-v3-horizontal.html) mockup. The hero spans the full container width with a horizontal 11-node stage timeline beneath it; the counter row sits below as 5 equal cards (avg cycle as the accented 5th); the Metrics tab is no longer empty; queue + recent activity gain client-side pagination; light is the new first-visit default.

## What landed

- **Full-width hero + 5-col counter row** ([scripts/spec_lifecycle/render_dashboard.py:903–1043](../scripts/spec_lifecycle/render_dashboard.py)). `_render_counter_cluster` returns 5 cards; the 4 plain counters (Drafts · Queued · In flight · Shipped) keep their shape, the 5th (`counter--accent`) carries the rolling-10 mean, ↓/↑ delta vs prior 10, and an inline SVG sparkline of the last 12 deployed cycles. `_render_avg_cycle_card` and the `[data-region="avg"]` swap path are deleted; `.strip` is `display: contents` so its children become direct kids of `.page`.
- **Horizontal in-flight stage timeline** ([render_dashboard.py:407–612](../scripts/spec_lifecycle/render_dashboard.py)). `_render_stage_row` → `_render_stage_node`; the `<ol class="stages">` block under the hero divider becomes `<div class="tl">` with `tl__rail`, `tl__rail-done` (width `calc((done_count/total)*(100% - 28px))`), and `tl__steps` grid. `data-stage-started-at` rides on the current node's `.tl__dur` so the live ticker still rewrites every second. The 28×28 nodes pulse on `--curr` (`@keyframes halo`), show `✓` on `--done`, `!` on `--fail`, and a centred dot on `--curr`.
- **Bootstrap client mirrors the timeline + history grid + pager** ([render_dashboard.py:2093–2473](../scripts/spec_lifecycle/render_dashboard.py)). New `STAGE_DEFS`, `computeStages`, `renderTimeline`, `renderPager`, and a top-level `pagerState` map. `renderHeroInflight` emits the full hero + divider + timeline so the timeline survives the 5s `/api/data` repaint (it was server-rendered only before — wiped on first refresh). `renderAllSpecs` emits the 6-column history grid; `renderQueue` / `renderFeed` emit the pager strip + `data-pager-page` row attributes.
- **History tab: Lifetime + Cycle columns** ([render_dashboard.py:802–871](../scripts/spec_lifecycle/render_dashboard.py)). New `_spec_lifetime_seconds` helper computes wall-clock from `created` (fallback `queued_at`) to `deployed_at`, promoting bare `YYYY-MM-DD` strings to midnight-UTC ISO timestamps. The grid moves from `76px 1fr 130px 100px 100px` (Spec · Title · Type · Status · Version) to `70px 1fr 110px 100px 90px 90px` (Spec · Title · Type · Status · Lifetime · Cycle). `_humanize_seconds` extended to weeks for multi-week lifetimes.
- **Metrics tab fully populated** ([render_dashboard.py:604–1196](../scripts/spec_lifecycle/render_dashboard.py)). `_render_metrics` body fully replaced. 3 top callouts (cycle-time WoW with ±% and tone-derived icon, dominant stage by share of mean across last 10 cycles, reconcile-drift count) + cycle-time line chart (last 22 deployed cycles, rolling-10 overlay, y-axis clipped at 60m with outlier count annotated) + stage-breakdown stacked bar (7 buckets via `_STAGE_GROUPS`) + throughput-per-ISO-week bars (last 8 weeks; current week in `--chart-purple`, prior weeks with graduated `--chart-blue` opacity) + by-type horizontal bars (last 30d, counts + mean cycle per type) + success-rate donut + authoring funnel. Empty-state copy ("Needs ≥ 1 deployed cycle with full timings") covers fresh repos. Helper `_compute_stage_durations(events)` derives per-bucket seconds for the stacked bar.
- **Pastel chart palette tokens** ([design-system/assets/styles/tokens-and-primitives.css:16–32, 200–211](../design-system/assets/styles/tokens-and-primitives.css)). Nine `--chart-*` tokens land in both the dark `:root` block and the `body.light` block. Documented in [design-system/SPEC.md §2.1 "Chart palette" sub-heading](../design-system/SPEC.md#L75). Scoped strictly to Metrics-tab charts — status chips, hero halo, in-flight chip all still read `--p-*`.
- **Pagination on Queue + Recent activity** ([render_dashboard.py:684–740](../scripts/spec_lifecycle/render_dashboard.py)). New `_render_pager(total, label)` helper + `PAGER_PAGE_SIZE = 10`. Rows on pages > 1 carry `data-pager-page="N"` + `hidden`. The bootstrap's `wirePager` attaches a delegated click handler to `document` so it survives the 5s repaint cycle; `pagerState` keys by section label so the user stays on their chosen page across `/api/data` refreshes. New `.pager` component lands in BOTH [`design-system/assets/styles/composed-components.css`](../design-system/assets/styles/composed-components.css) and [`src/dual_research/ui/static/components.css`](../src/dual_research/ui/static/components.css) in the same commit, per the DS-sync rule.
- **Light theme as the first-visit default** ([render_dashboard.py:1065–1097](../scripts/spec_lifecycle/render_dashboard.py)). The inline `_render_theme_init_script` no-localStorage fallback flipped from `'auto'` to `'light'`. The bootstrap's toggle-wiring fallback in `DASHBOARD_LIVE_JS` also picks `light` when no preference is stored. Existing users with a stored preference keep it.

## Deferred during implementation

- **Bootstrap timeline shows `—` for completed-stage durations after `/api/data` refresh** — the server-rendered timeline carries real durations on every completed `.tl__dur` cell (computed by `compute_stages`), but `DASHBOARD_BOOTSTRAP_JS:computeStages` only resolves `done` / `curr` / `queued` / `fail` statuses; it doesn't re-compute the per-stage second deltas. Result: the timeline durations are accurate on first paint and on the *current* stage (which the per-second `data-stage-started-at` ticker keeps live), but every completed stage's duration flips to `—` after the 5s repaint fires. Fix would extend `computeStages` to walk event timestamps the same way `stages.py:compute_stages` does for `duration_seconds`. Single-method change in `DASHBOARD_BOOTSTRAP_JS`.
- **Authoring-funnel DRAFTS count is partial** — `_render_authoring_funnel` (§2.4.7) uses `promoted_from_draft` to count drafts that *became* queued specs in the last 30 days. The spec said "current draft count + drafts promoted in last 30 days". The "current" half (count of files in `specs/drafts/` that haven't been promoted) is missing; the funnel's DRAFTS bucket therefore reads low on repos that have backlog drafts. `_render_metrics` would need a `len(drafts)` value passed through (currently it only gets `specs`); plumbing change in `render_index`.
- **Mockup-fidelity visual check** — the implementation followed the mockup's HTML/CSS contract, but no pixel-level comparison against `dashboard/mockups/dashboard-redesign-v3-horizontal.html` was done. The risk is small (mostly token swaps and structural mirroring), but minor spacing / proportion drift is possible. Browser smoke against `https://lexiz.github.io/dual-research/` after the GitHub Pages rebuild propagates would close this out.
- **Cycle-time line chart Y-axis cap of 60m may obscure outlier shape on bootstrap repos** — chose 60m (per mockup's "20m" axis bumped up to absorb queue-drain outliers in the 30–60m range). Repos with no outliers but mostly sub-10m cycles render with most points clustered at the bottom of the chart. Auto-ranging or a percentile-based cap (clip at p95) is a tunable that's deferred.
