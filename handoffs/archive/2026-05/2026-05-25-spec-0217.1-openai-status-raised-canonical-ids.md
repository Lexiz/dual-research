# Spec 0217.1 — STATUS arrays declare canonical IDs only

## What landed

The STATUS-block contract in [src/dual_research/protocol/prompts.py](src/dual_research/protocol/prompts.py) now declares the five action arrays (`RAISED_THIS_TURN`, `ADDRESSED_THIS_TURN`, `RESOLVED_THIS_TURN`, `ACKNOWLEDGED_THIS_TURN`, `WITHDRAWN_THIS_TURN`) as canonical-ID-only by contract. The pre-fix loose placeholders — `[list of IDs the orchestrator will assign]` in round-1 footers and the bare `[...]` in the shared `_status_footer_for_phase` helper — that let openai emit descriptive prose in the round-01-openai fixture at [tests/fixtures/spec_0217/phase2/round-01-openai.md:81](tests/fixtures/spec_0217/phase2/round-01-openai.md:81) are gone.

Concretely:

- **Inline round-1 footers** at the three sites flagged by [spec 0217.1 §3.1](specs/0217.1-openai-status-raised-canonical-ids.md) (phase 0 / phase 2 / phase 4 round-1) replace `[list of IDs the orchestrator will assign]` and `[...]` with `[<canonical-id>, ...]` for `RAISED_THIS_TURN`. The other four arrays stay `[]` in round-1 (factually empty) — the canonical-ID-only constraint applies but is satisfied by the empty-list shape.
- **Shared helper `_status_footer_for_phase`** replaces every `[...]` placeholder with `[<canonical-id>, ...]`, propagating the tightened wording to phase-0 round-N (`input_negotiation_prompt_v2`), phase-2 round-N (`plan_negotiation_round_n_prompt_v2`), phase-3 drafting (`drafting_prompt_v2`), and phase-4 round-N (`review_round_n_prompt_v2`).
- **Centralised callout constants** — `_STATUS_ARRAY_CONTRACT_CALLOUT` (general rule) and `_STATUS_ARRAY_CONTRACT_CALLOUT_ROUND1` (general rule + one-sentence clarification that the orchestrator assigns IDs from `### RAISE` blocks above) — render inline above every `## Status` block in the four round-1/round-N interaction prompts (phase 2 + phase 4). Centralising the wording means a future re-tightening lands at one site instead of four.
- **Reconstructor unchanged.** The STATUS-pass at [src/dual_research/ui/disagreements.py:587-610](src/dual_research/ui/disagreements.py:587) and the parallel pass in [src/dual_research/ui/questions.py](src/dual_research/ui/questions.py) continue to canonicalize-or-drop. The §8 spurious-ID drop at [src/dual_research/ui/disagreements.py:602-604](src/dual_research/ui/disagreements.py:602) remains the safety net for any agent that still drifts.

Three new regression tests at [tests/test_spec_0217_1_status_array_contract.py](tests/test_spec_0217_1_status_array_contract.py) pin substring `IDs only` in the rendered prompts (phase-2 round-1, phase-2 round-N via helper, phase-4 round-1) and antipodal absence of the pre-fix placeholders.

## What this fixes

The smoking-gun session `20260525-135006-backend-language-choice` (round 01, openai's turn) emitted:

```
RAISED_THIS_TURN: [
  "disagreement: Go #1 vs C# #1",
  "question: evidence threshold for Go AI-coding-agent advantage",
  ...
]
```

Spec 0217's STATUS-pass parsed this and dropped every entry as a spurious ID (it couldn't canonicalize the prose into `D-…` / `Q-…` form). Later canonical-ID closures from openai (`D-plan-g-01..05` RESOLVED at round 3, `Q-plan-g-02` RESOLVED, `Q-plan-g-01` WITHDRAWN) were also dropped because the spurious-ID mitigation rejects STATUS-listed IDs that were never `raised` in any prior round. Net effect: the entire openai-side negotiation never reached the reconstructed ledger.

The contract-layer fix prevents the descriptive-string substitution from happening in the first place. Existing fixtures captured under the pre-fix wording continue to be silently dropped — that's the right behaviour for legacy / drifted input.

## What's NOT in this spec (per §7)

- **Reconstructor-side canonicalization of descriptive strings (option (b))** — explicitly not pursued; would re-fragment the source of truth.
- **Regenerating the round-01-openai fixture** with canonical IDs — fixture stays as-is; it's load-bearing for spec 0217's Test 5.7 (asserts the descriptive-string array is silently dropped).
- **`ProtocolViolation` event for non-ID STATUS entries** — could be added as defense-in-depth in a follow-up if drift persists; today the STATUS-pass continues to silently drop.
- **Phase-0 STATUS-array regression test** — phase 0 inherits the fix via the helper update (§3.2), but no new phase-0 test was added.
