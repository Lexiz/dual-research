# Spec 0227.1 — Reconciler skips markdown-link display-text citations

## What landed

- Added `LINK_DISPLAY_RE` module-level regex and `_scrub_link_display_text(body)` helper in [`scripts/spec_lifecycle/reconcile.py`](scripts/spec_lifecycle/reconcile.py). The scrubber replaces every `[display](href)` display region with spaces of equal length, preserving byte offsets. Pattern: `r"\[([^\]\n]*?)\]\(([^)\n]*?)\)"` — non-greedy, single-line, no nesting attempted (matches markdown's own rendering of nested brackets as literals).
- Wired the scrubber into `_extract_citations` — the function now reads `body`, computes `scrubbed = _scrub_link_display_text(body)`, then runs `CITATION_RE.finditer(scrubbed)`. Display-text shadows of `path.ext:line` no longer enter the citation set; hrefs and plain-prose citations continue to match exactly as before. `Citation.raw` is byte-identical for surviving (non-display) matches because non-link regions are unchanged.
- Five new tests at [`tests/test_spec_0227_1_reconciler_skip_display_text.py`](tests/test_spec_0227_1_reconciler_skip_display_text.py) — display-text-only citation skipped, href-form citation extracted, plain-prose citation still extracted, mixed body returns href + plain only, plus a source-pattern pair locking the post-fix shape (positive: `_scrub_link_display_text(body)` inside `_extract_citations`; antipodal: no direct `CITATION_RE.finditer(body)` over the unscrubbed body).
- PATCH bump 1.46.1 → 1.46.2 in [`pyproject.toml`](pyproject.toml), [`src/dual_research/__init__.py`](src/dual_research/__init__.py), `uv.lock` refreshed. CHANGELOG entry under `## [1.46.2] — 2026-05-27` directly under `## [Unreleased]`. In-app changelog sidecar regenerated at [`src/dual_research/ui/static/version-notes.json`](src/dual_research/ui/static/version-notes.json) via `scripts/build_version_notes.py` (216 entries).
