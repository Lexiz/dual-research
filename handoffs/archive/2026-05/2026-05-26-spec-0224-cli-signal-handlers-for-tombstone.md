# Spec 0224 handoff — Fix: CLI registers SIGTERM/SIGHUP/SIGINT cancel handlers so the 0222 tombstone fires on raw signal kills

Ships v1.45.5. Closes the signal-side gap left by spec 0222. Raw `SIGTERM`, `SIGHUP`, and `SIGINT` delivered to the local-CLI orchestrator now route into Python's exception machinery as `asyncio.CancelledError`, which the spec 0222 `except BaseException` at [src/dual_research/orchestrator/run.py:548](src/dual_research/orchestrator/run.py:548) already tombstones. The Area-5 liveness invariant ("for every `run_started`, exactly one terminal event is emitted and `metrics.ended_at` is set") now holds for the three signal classes that previously bypassed it entirely.

## What landed

- `src/dual_research/cli.py` — added `import signal`, `from typing import Coroutine`, and a new helper `_run_with_signal_handlers(coro)` (~30 lines, body at the top of the module just before `_build_parser`). The helper grabs the running loop + the current task, iterates `("SIGTERM", "SIGHUP", "SIGINT")` via `getattr(signal, name, None)` so the import stays clean on platforms missing `SIGHUP`, calls `loop.add_signal_handler(sig, main_task.cancel)` for each (wrapped in `try/except NotImplementedError` for the Windows path), awaits the inner coroutine, then removes the handlers in a `finally:` for test/loop hygiene. Both `asyncio.run` sites are wrapped: the `_ingest` entry at line 314 (was 282) and the `run_session` entry at line 384 (was 352). No other `asyncio.run` sites in `src/` (verified via `grep -rn asyncio.run src/`).
- `tests/test_spec_0224_signal_handler_tombstone.py` — 3 new behavioural tests via a shared `_drive_signal_run` helper that patches `orch_run.run_phase0` to a 30-second `asyncio.sleep`, schedules `os.kill(os.getpid(), <signal>)` after 0.1s, awaits `cli._run_with_signal_handlers(orch_run.run_session(...))`, and asserts (a) exactly one terminal event on disk, (b) it is `run_failed` or `run_aborted`, (c) `metrics.ended_at` is non-null. Tests cover `SIGTERM` (Test 1), `SIGHUP` (Test 2, mac-local-CLI most-likely-death case), and `SIGINT` (Test 3, plus the `error_type=CancelledError` assertion that confirms the new handler path ran rather than the legacy `KeyboardInterrupt` path).
- `CHANGELOG.md` — new `## [1.45.5] — 2026-05-26` section under `## [Unreleased]`. Bumps `pyproject.toml`, `src/dual_research/__init__.py`, and the `uv.lock` mirror to 1.45.5 (PATCH per `version_bump: bug`).
- `src/dual_research/ui/static/version-notes.json` — regenerated via `scripts/build_version_notes.py`. Now 213 entries (was 212), with v1.45.5 at the top.

## Decisions made during implementation

- **No changes to `run.py:548` or the `_terminal_written` finally-fallback.** Spec §6 said "`run.py:548` `except BaseException`. Unchanged. This spec just routes new exception sources (SIGTERM/SIGHUP via CancelledError) into the existing handler." Spec §8 risk #2 nevertheless suggested gating the except-block's tombstone-write on `if not _terminal_written:` to defend against a "second terminal event written after a successful run_completed" race. Walking the success path's bytecode + asyncio cancellation semantics: between `transcript.write("run_completed", ...)` at [run.py:525](src/dual_research/orchestrator/run.py:525) and `_terminal_written = True` at [run.py:532](src/dual_research/orchestrator/run.py:532) there is no `await`, so the signal-handler-injected `CancelledError` cannot interleave. If cancellation arrives after success-path returns, the `CancelledError` raises at the next `await` (inside the `finally:` push-task drain at [run.py:608](src/dual_research/orchestrator/run.py:608)) — that propagates out of `finally:` without re-entering the `except` block, since the try-body completed normally. Race not reachable. Kept the fix scoped to `cli.py`. Mentioned this analysis in the spec body's §8 paragraph for future reviewers.
- **Helper signature uses `Coroutine` annotation, not `Awaitable`.** Both work; `Coroutine` is the precise type for the two callers (`_ingest(...)` and `run_session(...)`). Imported from `typing`.
- **`add_signal_handler` failures are silenced, not surfaced.** `NotImplementedError` (Windows) is caught and skipped per the helper loop; `getattr(signal, name, None)` guards the missing-`SIGHUP`-on-Windows attribute lookup. The orchestrator is mac-local-CLI today (Cowork resume snapshot §4) so neither path fires in practice. If the orchestrator ever targets Windows, the helper degrades gracefully: no handlers installed, behaviour reverts to today's bare `asyncio.run` (`SIGINT` still raises `KeyboardInterrupt` via CPython default, which the spec 0222 handler catches; `SIGTERM` / `SIGHUP` are no-ops on Windows anyway).
- **Symmetric protection on the `_ingest` entry.** Spec §3 said "ingest is short-lived and rarely produces a transcript worth tombstoning, but applying the same wrapper costs nothing and keeps the two entries symmetric. Apply." Applied — both `asyncio.run` sites now wrap through `_run_with_signal_handlers`.
- **Test fixture style mirrored spec 0222's `test_baseexception_path_writes_terminal_event_and_re_raises`.** Same `_FAKE_CREDS` shape, same `_make_session(tmp_path)` helper, same `_read_events(session_root)` helper, same monkeypatch-`run_phase0` pattern. The differentiator is the `os.kill(os.getpid(), sig)` trigger inside an `asyncio.create_task` callback that fires 0.1s after the run is in-flight.

## Operational notes

- **Coverage scope.** This spec covers the three signals CPython users actually deliver to the orchestrator in normal local-CLI operation: `SIGTERM` (process supervisors, `kill -TERM`), `SIGHUP` (terminal-window close, SSH disconnect, laptop sleep on macOS), `SIGINT` (Ctrl-C). `SIGKILL`, OOM-kill, and hard-crash remain impossible to handle in-process — the kernel terminates without notification. A sidecar watchdog covering those is deferred to a follow-up spec per Cowork resume snapshot §3 ordering ("only build this if a silent death recurs after spec 0224 ships").
- **SIGINT UX swap.** Registering `SIGINT` converts Ctrl-C from raising `KeyboardInterrupt` (CPython default) into raising `asyncio.CancelledError` (via the cancel handler). Both flow through `except BaseException` and produce a tombstone, so the observable outcome is the same — but the `error_type` field on the `run_failed` transcript event changes from `KeyboardInterrupt` to `CancelledError`. Test 3 explicitly locks in this swap. If the swap ever turns out to be undesirable, drop `SIGINT` from the helper's tuple — Python's default SIGINT path already raises `KeyboardInterrupt`, which 0222 tombstones correctly.
