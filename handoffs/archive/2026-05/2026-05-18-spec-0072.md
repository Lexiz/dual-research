## What shipped

Kind-axis filter row anchored left, agent+status axis centered with tighter `gap: 6`. Every critique filter chip now has a `title` tooltip explaining what it filters. Drift status chip visually disables (opacity 0.4, cursor not-allowed) when Questions is the active kind filter, with auto-reset to "All". Phase 4 Issues and Comments now render in their own separate CollapsibleSections instead of being mixed into the status-based DRIFT/OPEN/RESOLVED sections. Summary tab opens with a generated three-sentence copy: sentiment verdict (Mostly positive / Mostly negative / Mixed / Inconclusive), qualitative breakdown of questions/disagreements/issues/comments/claims, and a drift note if applicable. Summary copy rendered via `<Markdown>`.

## Risks the next spec should know about

- **PaneToolbar height is now flexible** — `minHeight: 44` instead of `height: 44`. All PaneToolbar usages (Timeline toolbar, Critique toolbar) will now expand if content wraps. If a downstream spec adds content to a PaneToolbar, it will grow vertically instead of clipping. This is intentional.
- **Phase 4 Issues are now in a separate section** — When `selectedPhase === 4`, issues no longer appear in OPEN/RESOLVED/DRIFT status-based sections. They have their own CollapsibleSection. The `issueItems` array is only populated for Phase 4; in other phases issues go through normal `pushItem()` flow.
- **Summary copy is client-computed** — No backend changes. The sentiment verdict thresholds (>70% resolved + <20% drift = positive, <40% resolved or >40% drift = negative, else mixed) are in CritiqueSummaryView. If the aggregator later exposes `run.summary`, the frontend logic should be replaced.
- **ReconcileChip 5-state preserved** — untouched, not in scope.
- **localStorage keys** — new keys: `dr_crit_{runId}_{phaseId}_issues` and `dr_crit_{runId}_{phaseId}_comments` for the Phase 4 split sections.
