# Spec 0212.1 — Lock the spec 0212 explicit-cleanup ordering invariant

PATCH test-only addition. Closes the ordering-blind-spot the spec 0212 source-pattern test suite shipped with.

## What landed

One new assertion in [tests/test_spec_0212_post_merge_doctrine.py:151](tests/test_spec_0212_post_merge_doctrine.py:151) — `test_step_19_re_detach_precedes_branch_delete`. It scopes to step 19's body via the existing `_step_block` helper, then asserts:

1. **Presence** — both `^\s*git\s+checkout\s+--detach` and `^\s*git\s+branch\s+-D\s+"\$BRANCH"` match somewhere in the block.
2. **Ordering** — the first detach line index is strictly less than the first delete line index.

The regex is anchored at start-of-line (allowing leading whitespace) instead of using a bare substring search per the spec's literal text. The spec body's §2.1 wrote `re.compile(r"git\s+checkout\s+--detach")` but step 19's explanatory prose at line 14 of the block contains both commands as inline-backtick references (e.g. `` `git branch -D "$BRANCH"` fails when the worktree is still on `$BRANCH` ``). A bare regex finds the prose `git branch -D` at block-line 14 *before* the shell `git checkout --detach` at block-line 19, producing a false-fail. The anchored regex skips the prose and matches only executable shell lines. The deviation honors the spec's stated intent (lock the cleanup-block command ordering) while making the assertion robust to the surrounding doctrine prose.
