## What shipped

Critique detail rendering unification with four changes. Disagreement expanded detail rebuilt from old CONTESTED POINT + PROGRESSION vertical-rail pattern to QuestionThread-style turn cards: contested point renders as the question body (via Markdown), each progression entry renders as an agent turn card with action chip (raised/conceded/aligned/pushed back/rejected), and a resolution footer shows the outcome. QuestionThread extended with `kind` prop accepting 'question' (default) or 'disagreement'. Issue and Comment card bodies now render via `<Markdown>` instead of raw text, fixing visible `**bold**` asterisks and unstyled `>` blockquotes. New `<QuoteCallout>` primitive added for `.quote` fields on critique cards (styled left border + italic + muted background). Also fixed disagreement Position data field references (`claudePosition`/`gptPosition` were previously referenced as `d.claude`/`d.gpt`, which were undefined).

### Mid-flight refinements

- **D1 (Disagreement detail)** -- Draft proposed a full `THREAD_CONFIG` const dict with per-kind action vocabulary and tone mappings. Implemented more simply: the existing progression data already has `action` field values (raised/conceded/aligned etc.) that map directly to QuestionThread's `verdict` prop. No separate config dict needed; the QuestionThread primitive handles both kinds with the same rendering logic, just different `kind` prop for header display.
- **D7 (QuoteCallout)** -- Draft proposed regex parsing of `> quote:` lines within body text. Implemented as a dedicated component for the existing `.quote` fields on Issue/Comment objects instead, since Markdown rendering (D3) already handles `>` blockquote syntax in body text.
- **D11 (Issue/Comment metadata chip row)** -- Deferred. Current mono-text footer (`flagged by Claude . first seen R1`) is functional. Not worth the churn for this spec.
- **Position data fix** -- Discovered `d.claude`/`d.gpt` fields don't exist in actual run data. The correct fields are `d.claudePosition`/`d.gptPosition`. Added fallback to both field names.

## Risks the next spec should know about

- **QuestionThread now accepts `kind` prop** -- Default is 'question'. When kind='disagreement', turns render `verdict` as action labels and `quote` through Markdown. If a downstream spec adds more kinds (issue/comment), extend the same pattern.
- **`agent: 'both'` turns** -- QuestionThread now handles `agent: 'both'` by falling back to Claude's visual slot. The label shows "Both". If a downstream spec needs different visual treatment for `both`, update the turn rendering in QuestionThread.
- **QuoteCallout** -- New primitive on `window`. CSS class `.quote-callout` in components.css. Uses token variables only.
- **Markdown in QuestionThread** -- String `question` bodies and disagreement `quote` fields now render through `<Markdown>`. If the next spec passes JSX as question body, it passes through unmodified (typeof check).
- **ReconcileChip 5-state preserved** -- untouched, not in scope.
- **Issue/Comment `after` fields** -- Still rendered as inline italic text, not QuoteCallout. These are "what happened after" metadata, not quotes.
