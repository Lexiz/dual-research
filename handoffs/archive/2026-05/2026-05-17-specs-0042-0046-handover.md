The session covered five specs across two clean halves:

**Half 1 — three specs shipped (0042 → 0043 → 0044):**

1. **0042 — Critique data integrity** ([PR #43](https://github.com/Lexiz/dual-research/pull/43)). UI surface correctness. Parser learned Phase 1's `## N. Claims I Expect…` + `## N. Open Questions` sections; new `kind="claim"` on wire + `Run.claims` array; Phase 2 R1's `## Diff vs … Phase 1` re-bucketed `disagreement → claim` (semantic correction — R1 enumerates contested points being *raised*; only R≥2 turns them into held disagreements); aggregator always-creates empty `phaseReviewItems` buckets so absence-as-empty ambiguity disappears; `Run.current_draft_path` populated on every snapshot; `StatsChips` reads from parsed-item arrays (not agent self-counters); `reviewItemsFor` bucket-key bug fix (snake_case → camelCase — this was the actual root cause of the long-standing empty-right-pane mystery; the lookup was always returning `undefined`); markdown setext-heading bug (`---` after a paragraph was rendering the paragraph as `<h2>`) fixed via a `_padSetextDividers` pre-pass.

2. **0043 — Cross-round ledger + standing-items input + conservative convergence** ([PR #44](https://github.com/Lexiz/dual-research/pull/44)). The data + protocol foundation for "trust through verification." New `src/dual_research/ledger/` package with `LedgerEntry` / `LedgerState` / `LedgerStatusTransition` / `LedgerDrift` dataclasses; `build_phase_ledger(session_dir, phase)` walks turn files chronologically and applies per-kind closure transitions; **no new agent output required** — the ledger is built by parsing what agents already write. `## Standing items from prior rounds` injected into R≥2 prompts so the LLM gets structured prior-state as input. Convergence cross-check: `is_plan_agreed` + `is_review_approved` accept an optional `ledger_open_count` parameter; a phase terminates only when both agent self-counters AND ledger open-set agree the open-set is empty. Kill-switch `DR_LEDGER_MODE=legacy` falls back to self-counter-only behaviour. Wire surface: `Run.phase_ledgers: dict[int, list[LedgerEntry]]` + `Run.drifts`. Frontend got a `LedgerDriftChip` on the Critique pane header; `GhostedAnnotation` component defined but not yet wired (deferred to spec 0046's visual rework). On partner-vetting the ledger surfaces 15 ghosted questions that pre-spec convergence accepted as resolved — the drift event fires cleanly.

3. **0044 — Turn-input semantics + per-turn badges + side-by-side framing** ([PR #45](https://github.com/Lexiz/dual-research/pull/45)). Frontend-only consumption of spec 0043's ledger. Dropped the per-turn `negotiating` / `reviewing` status pill (phase header already labels the phase). `✓ agreed` / `✓ approved` pill now only renders on the LAST turn of a phase that converged with zero open ledger entries (via new `isFinalConvergedTurn(item, run)` helper); pre-spec the pill mis-signalled convergence per-agent mid-loop. Per-turn count chips redesigned as explicit `+raised  −resolved` per kind via new `computeChipDeltas(run, item)` — `+5 Q  −1` / `−3 prior Q` / `+10 Cl`. Side-by-side modal left pane gets phase-aware document tabs via new `leftPaneTabsFor` + `NegotiateDocTabs` strip naming what the agent actually had as input (other's prior turn / other's draft / brief / your draft / current converged draft). Right-pane empty-state copy is action-specific (no activity / only-closed / raised-but-unanchored). Phase 1 plan-draft modal gains a `Phase1ItemStrip` above the draft body — clickable chips for each Phase 1 claim/question that jump the left brief pane via `scrollAndFlash`. `composeSentiment` reads the ledger for per-phase open counts. Notable on partner-vetting: `✓ agreed` correctly does NOT appear on any P2 turn — the ledger sees 15 ghosted questions, the phase isn't system-converged. The absence is the honest signal.

## Validated but unresolved

1. **Phase 4 sibling-key collapse.** (Pre-existing, called out in the 0038-0041 handover.) The per-turn key derivation `phase{N}_round{R}_{agent}` collides on `phase4-r1-claude` and `phase4-r1-claude-repair` siblings, so the Consumption tab's per-card detail under-reports for runs with repairs. The agent-level rollup includes both; only per-card detail is affected. Pre-existing; not in any of this session's specs.

2. **Pre-existing `drafter=null` + `status=completed` crash.** Still unresolved. 5 of 10 local runs affected. Mitigation: 2-char fix (`meta?.name`); deferred to a future patch.

3. **1h-cache underbilling permanently lost on pre-0039 runs.** As documented in the 0038-0041 handover. Partner-vetting's recompute lands at $9.86 vs provider dashboards' ~$12; the gap is unrecoverable for pre-spec transcripts.

4. **Phase 2 question-closure detection accuracy.** Spec 0043's ledger marks questions `answered` only when their body-prefix shows up in a later round's `## Answers to:` section via positional + verbatim-match. On partner-vetting this leaves 15 questions as `open` at end-of-phase (the drift signal). Some of these may be real ghosts; some may be false-negatives from a too-strict matcher. Tuning the matcher (or accepting the drift signal as "agents really did ghost these") is a follow-up.

5. **`raised_turn_key` empty on ~1 disagreement entry on partner-vetting** (`d-01`). The reconstructor populates turn keys for most disagreements via spec 0034's pass, but a small number get an empty string. Tests now assert >80% populated as a regression guard. Real fix is to backfill the missing keys; deferred.

## Workflow (per [CONTRIBUTING.md](../CONTRIBUTING.md))

```
spec → branch → implement → tests + preview-verify → version-bump →
CHANGELOG + VERSION_NOTES → PR (admin squash-merge) → fly deploy → STOP
```

Per-spec discipline:

- Spec file already exists at `specs/NNNN-<slug>.md` with front-matter `status: proposed`. Flip to `in-progress` when starting; flip to `merged` + populate `pr: "<url>"` after merge.
- Branch: `spec/NNNN-<slug>` (matches filename).
- Version bump: `pyproject.toml` + `src/dual_research/__init__.py` simultaneously. Match the spec's `target-version` field.
- CHANGELOG: move `[Unreleased]` to a versioned heading. New `[Unreleased]` placeholder.
- `VERSION_NOTES` at the top of `how-it-works.jsx` for user-visible changes.
- PR: `gh pr create --label "spec/<label>" --title "Spec NNNN — <title>" --body ...`. Use heredoc for the body.
- Merge: `gh pr merge <PR#> --admin --squash --delete-branch`.
- Deploy: `fly deploy`. Verify with `curl https://dual-research-alex.fly.dev/api/health`.
