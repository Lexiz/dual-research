# Spec 0222 handoff — Fix: orchestrator liveness tombstone + remove asymmetric stdout streaming

Ships v1.45.3. P0 silent-death fix: six runs since 2026-05-24 died with `turn_inputs` as their last transcript line — no `run_failed` / `run_aborted` / `run_completed`, `metrics.ended_at = null`. Indistinguishable from "still running" to the dashboard, the queue runner, and any reaper that tailed the transcript. Establishes Area 5 of the unified contract (previously uncontracted): **for every `run_started`, exactly one terminal event is emitted and `metrics.ended_at` is set — including on `BaseException`.** Until this lands, every downstream observability gap (e.g. Bug A's silent `continue` at `deep_research.py:482`) is invisible behind the missing-tombstone wall.

## What landed

- `src/dual_research/orchestrator/run.py` — three coordinated changes inside `run_session`. **§4.1 widened handler:** [run.py:543](src/dual_research/orchestrator/run.py:543) changes from `except Exception` to `except BaseException`. The pre-fix handler let `asyncio.CancelledError`, `KeyboardInterrupt`, `SystemExit` (none of which subclass `Exception`) escape entirely. Post-fix: `metrics.mark_done()` + `metrics.save(...)` and `bus.publish(RunFailed(...))` are each wrapped in their own best-effort `try/except BaseException` block so a shutdown-time failure in either cannot suppress the load-bearing `transcript.write("run_failed", ...)` tombstone, then `KeyboardInterrupt` / `SystemExit` / `asyncio.CancelledError` are re-raised after the tombstone so structured-concurrency cancellation propagates correctly and shells see the right exit code. **`_terminal_written` flag** initialised at the top of the orchestrator body and set to `True` immediately after the success-path `transcript.write("run_completed", ...)` at [run.py:521](src/dual_research/orchestrator/run.py:521) and immediately after the new except-path `run_failed` write. **§4.3 / §4.4 defensive `finally:` fallback** at [run.py:575](src/dual_research/orchestrator/run.py:575): order is push-watch drain → metrics save → tombstone write (terminal event included in the final hosted-UI push); runs only when `_terminal_written == False`; both inner blocks wrapped in `try/except BaseException: pass` so the fallback cannot raise; writes `event="run_aborted"` with `reason="terminal-event-fallback"` so the audit trail distinguishes a happy-path-failed-twice abort from a normal `run_failed`.

## Decisions made during implementation

- **`bus.publish` and `metrics.save` each get their own best-effort wrapper, not one shared wrapper.** Spec §4.1 said "wrapped in an inner `try / except BaseException` so a bus-publish failure during shutdown cannot suppress the transcript tombstone". A literal single wrapper around the whole `metrics.save + bus.publish + transcript.write` triple would defeat the stated purpose — a bus.publish failure inside the shared try would short-circuit the transcript.write, which is exactly the failure mode the spec exists to prevent. Picked the structurally correct interpretation: separate inner try/except around metrics.save, another around bus.publish, then `transcript.write` runs unconditionally with `_terminal_written = True` set immediately after. This also reads correctly against spec §4.3's analogous "inside its own `try / except BaseException: pass`" pattern for the finally fallback (two separate try blocks for `metrics.mark_done`+save and `transcript.write`, so a failure in one doesn't suppress the other). If `transcript.write` itself raises (corrupt handle, the Test 2 scenario), `_terminal_written` stays `False` and §4.3's finally writes `run_aborted` as the load-bearing fallback.
- **Re-raise check uses `isinstance(e, (...))` rather than catching three separate exception classes.** The widened `except BaseException as e:` handler needs to re-raise three classes (`KeyboardInterrupt`, `SystemExit`, `asyncio.CancelledError`) while letting normal `Exception` subclasses fall through to the `return RunResult(exit_code=EXIT_RUNTIME, ...)` path. `isinstance` keeps the tombstone-write code in a single linear path and the re-raise as a tight three-line tail — cleaner than three sibling except blocks.
- **Reconciler's "mechanical drift" flag for §4.1/§4.2/§4.3 was a false-positive — treated as clean.** `uv run python -m scripts.spec_lifecycle.reconcile` reported 6 mechanical drifts on bare filenames (`run.py:543`, `dr_run.py:319`, etc.). The spec body uses bare filenames in section headings (`### 4.1 — \`run.py:543\` — widen the handler`) alongside full-path markdown links in citation contexts (`[src/dual_research/orchestrator/run.py:543](src/dual_research/orchestrator/run.py:543)`). The reconciler matched on the headings' short forms. Verified by inspecting all six cited lines on `src/dual_research/orchestrator/{run,dr_run,deep_research}.py` — every cited line matched the spec's claimed content exactly. No drift, no patches. Emitted `reconcile_complete` with `verdict:"clean"` and `note:"reconciler-false-positive-bare-filenames-match-on-fullpath"`.
- **Scoped the stream_to fix to the two explicit call sites; did not flip the `_call.py:66` default.** `run_one_call`'s `stream_to` parameter still defaults to `sys.stdout` ([_call.py:66](src/dual_research/orchestrator/_call.py:66)). Other callers (`phase{0,1,2,3,4}.py`, `repair.py`) inherit that default. The spec explicitly scoped §4.2 to the two explicit `sys.stdout`-on-claude-only sites that produced the openai/claude asymmetry; flipping the upstream default is a contract change for every caller and would belong in its own spec. Kept the change minimal — claude turns now match openai turns at the asymmetric sites, the legacy phase{0,3,4}.py paths (post-spec-0114 not driven by production per the `run.py:28-30` comment) inherit the default unchanged.
