## [0.41.0] — 2026-05-17

### Added

- **Authoritative cross-round ledger + standing-items input + conservative convergence** ([spec 0043](specs/0043-cross-round-ledger-and-conservative-convergence.md)) — the system now maintains a programmatic record of every claim / question / disagreement / issue / comment raised across each phase's rounds, derived from the existing parsed sections in each turn file. **No new agent output required** — the ledger is built by parsing what agents already write. Three changes that work together: **(1) Ledger package (`src/dual_research/ledger/`)** — `LedgerEntry` / `LedgerState` / `LedgerStatusTransition` / `LedgerDrift` dataclasses; `build_phase_ledger(session_dir, phase)` walks turn files chronologically and applies per-kind closure detection (questions: `## Answers to:` positional + verbatim-match; disagreements: D-N appearance in `## Resolved or non-blocking differences` / `## Final-surfaced disagreements`; claims: D-N suffix match against substantive-disagreements / resolved / final sections for escalation; issues: latest-round body-marker semantics; comments: terminal `noted`). Ghosted-rounds counter accumulates each round an open item received no addressing signal. **(2) `## Standing items from prior rounds` injected into R≥2 prompts** via `negotiation_turn_prompt` + `review_turn_prompt`. The orchestrator (`phase2.py` / `phase4.py`) builds the section per-agent before composing each round's prompt; items raised by the other agent surface first (grouped "what's still on them" vs "what you still hold"). Soft instruction — items left unaddressed surface as ghosted in the UI. Bounded at 30 entries / 3000 chars with a truncation footnote. **(3) Conservative convergence cross-check** — `is_plan_agreed` + `is_review_approved` accept an optional `ledger_open_count` parameter; convergence terminates only when both the agent self-counters AND the ledger open-set agree. Drift signal surfaced on `Run.drifts: list[LedgerDrift]` for end-of-phase mismatches between agent counters and ledger counts. **(4) Wire surface** — `Run.phase_ledgers: dict[int, list[LedgerEntry]]` keyed by phase (2, 4). UI binds `run.phaseLedgers[2|4]` as the canonical source for cross-round display. **(5) Kill-switch** — env flag `DR_LEDGER_MODE=legacy` falls back to self-counter-only convergence (skips ledger check; omits standing-items section). Default `enforce`. **(6) Frontend** — small `LedgerDriftChip` on the Critique pane header surfaces per-phase drift events with a tooltip breakdown; `GhostedAnnotation` component added (forward-compatible for spec 0046's visual rework). **33 new tests** across `tests/ledger/` (models, build transitions, prompt composer, kill-switch) + `tests/protocol/test_convergence_ledger.py` + `tests/ui/test_aggregator_ledger.py`. 652 total green (was 619). The wire-format additions (`Run.phase_ledgers`, `Run.drifts`) are foundational for spec 0046's Critique pane redesign; 0043 itself ships the data + a minimal drift indicator.

### Deferred to future specs

- Per-card ghosted-N-rounds annotations in the critique panel (spec 0046 visual rework will wire `GhostedAnnotation` into `QuestionCard` / `IssueCard` / etc.).
- Removing the `OPEN_QUESTIONS:` / `OPEN_ISSUES:` self-counters from the protocol prompts (kept as sanity-signal; future spec can deprecate once drift is rare).
- Cross-phase ledger queries (e.g. "which Phase 2 claim hardened into a Phase 4 issue?"). Phase 2 and Phase 4 ledgers are independent.

## [0.39.0] — 2026-05-16

### Fixed / Added

- **Critique classification + load-time resilience + sentiment paragraph + tighter cards** ([spec 0041](specs/0041-critique-classification-and-resilience.md)) — four issues from a single review pass over the Phase 4 / critique surface. **(1) Phase 4 conflated issues, comments, and questions under one "questions" bucket.** Real semantic bug. The protocol uses three distinct sections — `## Open questions for {other}` (questions one reviewer asks the other), `## Issue ledger (delta + currently open)` (items the reviewer found wrong with the *draft itself*, stateful and self-managing), and `## Comments on the current draft` (non-blocking commentary) — but `protocol/parse.py::extract_review_items` pulled items from all three and classified every entry as `kind="question"` (with the comment "Classify as question so the UI groups them"). `reconstruct_questions` then tried to thread answer linkage with a cross-round positional-match heuristic that was designed for actual questions. Two visible consequences on the partner-vetting run: the timeline showed `0 issues` + `APPROVED` (the protocol's terminal state for a successful review) while the critique pane showed `74 Q · 61 open` — three sections combined, none of which were real Q&A linkages. Spec 0041 splits the parser to emit `kind="issue"` / `"comment"` / `"question"` distinctly. New `Issue` and `Comment` dataclasses on `Run.issues` / `Run.comments`. New `ui/issues.py::reconstruct_issues` reads the agent's own `open`/`resolved`/`non-blocking` markers inside each Issue ledger entry as the canonical status — matching the agent's `OPEN_ISSUES: N` end-of-turn counter that the timeline chip already used. The parser also gains a bold-heading entry detector (`**C-1** — ...`) since Claude's ledger uses heading-style entries instead of numbered lists. Partner-vetting Phase 4 now correctly reports `30 I (30 resolved · 0 open) · 0 Q · 0 D · 33 C` — reconciling with the timeline's `0 issues` + `APPROVED`. **(2) Transient `HTTP 502` flash on initial run load fixed.** `useLiveRun` no longer stamps `error` on the first non-2xx response. Internal counter tolerates 3 consecutive failures before surfacing the error screen; once `run` is non-null a transient failure NEVER overwrites the data with the error screen (existing connected indicator dims naturally). First-load retries are paced at 1s / 2s / 4s before settling into 5s steady-state polling — so a cold-start Fly machine wake + Supabase materialise blip doesn't flash an error screen at all. **(3) Question / disagreement / issue / comment cards hard-truncate body at ~70 chars** before the CSS ellipsis kicks in. The column reads cleaner as a scannable list; the full body lives in the expanded surface and on the `title` attribute for hover. **(4) `composeSentiment` expanded to every phase with an overall sentiment lead.** Pre-spec Phase 0/1/3/5 returned `''` and Phase 2/4 produced terse two-sentence output. Now: `**Positive —** Claude approved the draft this round. No open issues this round.` / `**Cautious —** Claude's round-1 difference inventory. Raised 6 new questions. Standing: 6 open questions.` / `**Critical —** Claude did not approve; 5 open issues.` / `**Solid —** Claude delivered an independent Phase 1 draft.` / `**Done —** Final document emitted by Claude.` Bold-rendered inline via a small `renderInlineBold` helper. **(5) `CritiqueExplorer` renders four typed groups.** Type filter becomes `All / Issues / Questions / Disagreements / Comments` with per-kind pills (`I` warn, `Q` info, `D` warn, `C` neutral). Phase tab counts show `30 I · 0 Q · 0 D · 33 C` (zeros collapse). Summary tab table gains `I raised / I resolved / I still open` + `C noted` columns alongside the existing Q + D columns. **6 new tests** in `tests/ui/test_issues.py` (marker-wins-across-rounds, Claude bold-heading parsing, non-blocking ⇒ resolved, ID-token dedup across rewordings) + `tests/ui/test_questions.py` (Phase 4 issue-only turn produces zero questions). 610 total green.

## [0.37.0] — 2026-05-16

### Fixed

- **Cost-pipeline integrity — preserve metrics on resume, price the cache tier that was actually used, fold tool spend into the headline** ([spec 0039](specs/0039-cost-pipeline-integrity.md)) — audit of the partner-vetting run (2026-05-16) surfaced a roughly 4× under-report in the user-facing total (`metrics.json` said $2.45 against a recomputed ~$9.86). Three independent defects composed. **(1) Resume lost prior metrics.** `orchestrator/run.py:110` instantiated a fresh `Metrics()` on every session entry — no rehydrate from disk — so the final `metrics.save()` overwrote the pre-resume call list with only the resume-window calls. The aggregator's fallback at `ui/aggregator.py:211-215` was wired backwards: it only kicked in when metrics.json reported `total_cost_usd == 0.0`, so a non-zero resume-window total silently masked the rest of the run. New `Metrics.load_or_new(path)` rehydrates on every session entry; D3 inverts the aggregator's priority so the transcript is now the primary truth and metrics.json is the cold-start fallback. **(2) Cache writes priced at the 5-minute rate when the agent requested 1h.** `anthropic_agent.py:30` has requested `cache_control: {"type": "ephemeral", "ttl": "1h"}` (via the `extended-cache-ttl-2025-04-11` beta) since spec 0017, but `pricing.py:31` hardcoded `cache_write_per_mtok = 3.75` — the 1.25× = 5-minute rate. Anthropic bills 1h writes at 2× input. `ModelPricing` now splits `cache_write_5m_per_mtok` (1.25× input) and `cache_write_1h_per_mtok` (2× input); `TokenUsage` gains `cache_write_5m_tokens` + `cache_write_1h_tokens` (the aggregate `cache_write_tokens` stays as the sum for back-compat on the transcript wire shape); the Anthropic agent reads `usage.cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens` and prices each tier exactly. New run multi-round phases now bill correctly — old transcripts can't be retroactively re-attributed because they only carried the aggregate field. **(3) Web-search fees missing from every persisted total.** Spec 0031 D7 had carved `search_cost` out as a side-channel surfaced only in the Consumption tab's expanded panel. With (1) and (2) fixed, the gap between the headline and the invoice became obvious. New canonical `compute_full_cost(model_id, usage, searches)` is what stamps every persisted `cost_usd` (AgentResult, TurnEnded, CallRecord, metrics.json total, RunCompleted, Supabase `runs.total_cost_usd`); `compute_token_cost` is the renamed-but-preserved per-token helper, used for the breakdown ("of which tokens / of which web search"). `TurnEnded` event shape gains `cache_write_5m_tokens` / `cache_write_1h_tokens` / `search_cost`. `TurnTokenUsage` gains `token_cost` (= cost − search_cost, invariant). The Consumption tab relabels its "tool cost" line to "of which web search" — clear that it's a breakdown, not a separate charge. **(4) Transcript dedup by label.** Parse-error recoveries replay the same `turn_ended` label multiple times; the partner-vetting run had every `phase4-r*-*` label appearing twice (the naive transcript sum was $12.74; the deduped sum is $8.78). `load_run_snapshot` pre-filters the event stream to keep only the last occurrence per label; `_sum_transcript_cost` and the recompute tool follow the same convention. Sibling labels (`phase4-r1-claude` and `phase4-r1-claude-repair`) are NOT deduped — they're distinct API calls billed separately, and the agent-level rollup includes both. **(5) New `dual-research recompute-costs --run RUN_ID | --all [--push] [--dry-run]` subcommand.** Re-walks each run's transcript, recomputes every per-turn cost under the new pricing rules (folds search in; old transcripts get 5m attribution for cache writes since the per-TTL split was never recorded), rewrites `metrics.json`, and backs up the original to `metrics.json.pre-0039.bak` on the first invocation (idempotent — re-runs preserve the original-original). All existing local runs backfilled; `runs.total_cost_usd` on Supabase will be updated post-deploy via `recompute-costs --all --push`. **(6) UI breakdown.** `CostBadge` tooltip shows `${cost} (tokens $X · web search $Y)` when `searchCost > 0`. The CLI `[run]` summary line gains the same breakdown when search fees fired. **Note: totals on the run list & detail header will INCREASE for runs that used web search or 1h-cache writes** — the partner-vetting run's headline jumped from $2.45 to $9.86. **22 new tests** across pricing (per-TTL splits, `compute_full_cost` invariants, snapshot table), persistence (CallRecord shape, `Metrics.load_or_new` rehydrate + missing file + corrupt JSON + old-shape tolerance), aggregator (transcript-primary fallback, dedup by label, search-fee fold-in for pre-spec events), and `tests/audit/test_recompute.py` (dedup, idempotence, backup-once, dry-run, `--all` walks directory). 602 total green.

## [0.34.0] — 2026-05-16

### Added / Fixed

- **Web search audit foundation + protocol parser fixes + resume hardening + `--notion` repeatable** ([spec 0036](specs/0036-web-search-audit-foundation.md)) — closes the audit gap surfaced after the first full prod-tier run, plus six round-2 readiness fixes that touch the same parser + orchestrator surface. The unifying gap: when web search fires, dual-research only recorded an integer count — the queries, retrieved URLs, retrieved snippets, and per-citation `cited_text` were all read by the model and then discarded, so a human reviewer had no way to verify the model's claims against ground truth. **(1) Per-turn web-search audit capture.** New `src/dual_research/audit/` package with provider-neutral schema (`TurnSearchAudit` / `ToolEvent` / `ConsultedSource` / `Citation` / `TurnSearchFlags`), per-provider normalisers (`normalize_anthropic_search_audit` walks `web_search_tool_result` blocks + citation annotations; `normalize_openai_search_audit` walks `web_search_call` items + `url_citation` annotations), and a validator (`validate_search_audit`) that cross-references each citation URL against the consulted-source set and stamps four flags (`search_performed`, `cited_url_not_in_consulted_sources`, `citations_without_search_event`, `queries_missing_from_actions`). URL normalisation strips `utm_source=openai` and other UTM-style tracking params before set membership so OpenAI's appended-tracking-param URLs match clean Anthropic retrieval-set URLs. **(2) OpenAI now forces `search_context_size: "high"` + `include: ["web_search_call.action.sources"]` on every web-search call.** Closes the bulk of the "model hallucinates citations even though search ran" failure mode the OpenAI community thread documents — `high` gives the model more page content before generating, and `include` surfaces the full retrieval URL list (without it, only cited URLs come back). **(3) New `TurnSearches` event + on-disk persistence.** The orchestrator's `run_one_call` emits `TurnSearches` right after the agent returns, carrying the normalised audit dict. The aggregator's new `_on_turn_searches` handler runs `validate_search_audit` and writes the bundle to `session_dir/searches/<turn-key>.json` (parallel to spec 0033's `inputs/`), then stamps `TurnTokenUsage.search_audit_path`.
