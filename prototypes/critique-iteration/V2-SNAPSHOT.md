## 3. V2 patches applied on top of the workshop's iter-1 → iter-15 lock

### V2.A — iter-2 CSS block (`<style id="iter-2-collapse-iter12-lifecycle">`)

Located in `proposed.html` right after the iter-1 style block (around line 543 currently). Adds two rules:

```css
.item-card[data-expanded="false"] > .item-card__lifecycle {
  display: none;
}
.item-card[data-expanded="true"] > .item-card__lifecycle {
  display: flex;
}
```

**Why.** Iter-12 of the original workshop replaced the legacy `.item-card__body`
+ `.item-card__timeline` rendering with an injected
`<section class="item-card__lifecycle iter12">` wrapper, but the original
`workshop-collapse-affordance` rule only hid `.__body`, `.__timeline`,
`.__lifecycle-footer`, `.__sources`. The new wrapper wasn't in the list, so a
"collapsed" card kept showing the entire lifecycle conversation. This rule
closes that gap.

### V2.B — iter-15 JS auto-expand block neutralized

Inside `initCollapseState()` (around line 1311 currently), the block that read
`document.querySelectorAll('.phase-state').forEach(...).setAttribute('data-expanded', 'true')` is **commented out**. Replaced
with a comment block stating *"SUPERSEDED by user direction (2026-05-23): every
card stays collapsed by default in every phase. The side-by-side
collapsed/expanded view is no longer the goal; users open cards manually."*

The original iter-15 logic is preserved as a multi-line comment beneath the
SUPERSEDED note so the workshop history stays auditable.

**Why.** The original iter-15 b promoted "the first card with sources per
phase" to `data-expanded="true"` so the workshop could demo the expanded view
without a click. V2 reverses that: cards are collapsed *always*, including the
first-with-sources card.

### V2.C — Orchestrator/system lifecycle row + LIFECYCLE alignment

Two parts.

**JS change in `buildLifecycleRow()`** (around line 1160 currently):

- Added an `else` branch that renders a System chip when actor is null / orchestrator / system. Previous code skipped the provider chip entirely.

  ```js
  providerHTML = `<span class="chip tone-neutral no-dot lc-provider lc-provider--system">${leadingIconForAgent('system', doc)}<span class="chip-label">System</span></span>`;
  ```

- `modifierHTML` is now always an empty string. The original "via hard_cap" / "via timeout" / "via withdrawal" modifier chip is dropped — the verb chip itself (`capped` / `withdrawn` / `acknowledged`) already carries the outcome.

**CSS change in the iter-2 style block:**

```css
.item-card .item-card__lifecycle-hd {
  text-align: left;
  align-self: flex-start;
}
.item-card .lc-row[data-actor="orchestrator"],
.item-card .lc-row[data-actor="system"] {
  align-self: stretch;        /* critical — see "Why" below */
  align-items: flex-start;
}
.item-card .lc-row[data-actor="orchestrator"] .lc-row-quote,
.item-card .lc-row[data-actor="system"] .lc-row-quote {
  text-align: left;
}
```

**Why.** Orchestrator/system transitions previously rendered as
`[round 4][capped][via hard_cap]` with no agent badge, drifting toward the
centre of the card. V2 gives them a `[System]` badge so the conversation reads
as a proper three-party arc (Claude → GPT → System), **positioned at the left
edge identically to the Claude / GPT rows above**.

The critical bit is `align-self: stretch`. The parent
`.item-card__lifecycle` carries `align-items: center` (it's a rule shipped
to live via spec 0173). Claude / GPT rows *look* left-aligned only because
their long wrapping quotes make `.lc-row` as wide as the container — the
centring becomes a no-op. The orchestrator row has a short single-line quote,
so its `.lc-row` stays narrow and the parent's centring pushes it to the
middle. `align-self: stretch` overrides the centring on a per-row basis and
forces the orchestrator/system rows to span full width regardless of content
size. With that, `align-items: flex-start` on the row itself pins the chips
and quote to the left, matching the Claude / GPT rhythm exactly.

The LIFECYCLE overline gets the same treatment via `align-self: flex-start`
so it can't drift to centre at any viewport width.

**Revision history.**
1. *First V2 draft (2026-05-23 morning)* — right-aligned the orchestrator/
   system rows to mirror the right-edge state chip on the card head. User
   rejected: column rhythm should be uniform; system row at the same left
   edge as Claude/GPT, only the badge identity changes.
2. *Second V2 draft (afternoon)* — set `align-items: flex-start` on the row
   and `text-align: left` on the quote. The computed styles looked right
   (`alignItems: "flex-start"`) but the visual was still centred at wider
   viewports, because `align-items` controls children, not the row's own
   position relative to its parent.
3. *Third V2 (current)* — added `align-self: stretch` to override the parent
   `.item-card__lifecycle { align-items: center }` rule. The row now spans
   full width regardless of content length, and the system chip cluster lines
   up with the Claude / GPT chip clusters above. Verified at 1400px and
   1920px viewport widths: `rowLeft` and `chipsLeft` are identical across all
   three rows.
