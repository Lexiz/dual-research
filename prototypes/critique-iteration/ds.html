Critique card · ItemCard + Sources

§13 · components · NEW · spec 0144

The canonical per-card primitive for every critique item. All four kinds — Question, Disagreement, Issue, Comment — render with the same layout; only the category chip varies. Each card carries header chips, the item text, an optional Evidence needed helper, a vertical Lifecycle timeline of transitions, a terminal-state footer, and (when N>0) a SOURCES (N) segment that itemises each consulted source the agent cited when addressing the item.

view_agenda
Stacking order (top → bottom)
  1. Header chip row. {id} (mono inline, not a chip) · agent · kind · raised in rN · Sources N (when N>0) · right-aligned status chip.
  2. Body. Item text. When anchor_type !== 'none', a tinted blockquote follows.
  3. Evidence-needed helper. Italic line, rendered only when evidence_required === true: "Evidence needed — addresses must cite consulted sources."
  4. Lifecycle timeline. Vertical list of transitions; each row is round N · agent · verb with the reason in muted serif italic underneath.
  5. Footer. Single tinted line (ok-toned by default): ✓ {terminalState} at round N · M turns to converge. Rendered in any terminal state; never on open / addressed items.
  6. SOURCES (N). Vertical stack of <SourceRow> instances after a dashed top border. Hidden entirely when N === 0.

SourceRow — anatomy

One row per evidence record. Collapsed by default; click the chevron or the title to expand. The collapsed form carries title + host (and an ⚠ unverified chip when the validator flagged the record). The expanded form adds the URL, the search query, the fetched-at timestamp, the content excerpt (bounded scroll above 800 chars), and any unverified reason.

rule
The kind-agnostic invariant. All four kinds — Question, Disagreement, Issue, Comment — render with this exact stacking order. No kind-specific variant exists. A reviewer who sees an Issue or a Comment card that diverges from this anatomy is looking at a bug, not a variant.
visibility_off
Empty SOURCES segment is hidden. When the item has N === 0 evidence records, the entire SOURCES segment — label, border, and list — is removed from the DOM. A segment showing (0) on an item that never had source data would be misleading; the segment's presence is itself the signal.
warning
Unverified chip placement. The ⚠ unverified chip lives on the offending source row, never on the card header. A card with three sources where only one is flagged would mislead reviewers with a card-level chip — only the row in question is annotated.

QuestionThread (legacy)

§13b · components · LEGACY · pre-0114 fallback
history
Legacy fallback. The canonical critique-card primitive is now Critique card · ItemCard (§13) — it handles all four kinds (Q · D · I · C) and surfaces evidence sources per the spec 0144 contract. The thread component below is retained for pre-0114 archived runs whose items have no transitions[] array. Routing logic: Array.isArray(item.transitions) → <ItemCard>; else → <QuestionThread>.

Turn-by-turn conversation for a single critique item. Border-left tinted by status: open warn, resolved ok, drift err. Each row carries an agent pill (initial + name + round + verdict) and the agent's quote in serif italic. The header carries the qref badge — Q · 03 · [agent] · r1 — plus the resolution chip.
