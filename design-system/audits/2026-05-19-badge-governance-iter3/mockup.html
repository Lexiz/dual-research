§ 3. Governance rules

One primitive

  • <Chip> is the only chip primitive. Slots: leadingDot | leadingIcon | categoryBubble (mutually exclusive), label, value (large bold number), add (green +N), sub (red −N), trailingSuffix.
  • All legacy variants retire: StatChip, StatusInline, ConvergedChip, GhostedRoundsBadge, SearchChip, .drift-chip, critique-pane <Tab> filters, inline-text verdict rendering.

Category labelling — the evolution of 0115's rule

  • Old rule (0115): "Never use letter abbreviations like Q, D, I, C. Always the full word (plural)."
  • New rule: The filter chip row at the top of the Critique pane is the canonical legend — always shows [bubble] FullWord count. Elsewhere (timeline cards, phase headers, critique card headers), the dense category glyph bubble form is permitted: a 14 px colored circle containing the category's first letter, treated as a designed icon. Color carries the category identity; bubble + color is unambiguous given the legend is always one scroll away. This is NOT a bare letter abbreviation in the old sense — it's a typeset glyph in a designed container.
  • Tone-to-category mapping is fixed: Q = info blue, D = warn amber, I = err red, C = idle grey. Never swap.
  • Order is fixed: Q → D → I → C, left to right, every time. Allows reading down a column.

Composition rules

  • Provider chip is always its own chip and always FIRST.
  • Activity / round chip is its own chip, always SECOND.
  • No public-ID chips in card headers. The category chip + provider + round disambiguates; the raw ID is small mono inline text inside the card body.
  • Item lifecycle vocabulary = the 6 verbs from contract/lifecycle.py: raised, addressed, resolved, acknowledged, withdrawn, capped.

Status — never bare

  • Every timeline card carries a right-aligned status chip. No exceptions.
  • Values: running (live), ✓ alone (turn completed, IN_PROGRESS), ✓ agreed (turn emitted AGREED), queued (pre-run). capped appears only on critique item cards (not turn cards).
  • repair removed per spec 0114.

Numbers

  • Standing is the lead number (bold white). +N green = added this round. −N red = solved this round.
  • Reconciliation: standing(N) = standing(N−1) + added − solved. Numbers must agree down a column.
  • Zero-activity chips dim to ~55% opacity.
  • Cap suffix: · ⊘ N inside chip when items orchestrator-capped this round.

Drift (clarified per 0114)

  • No run-wide drift counter. ⚠ ledger drift modifier chip appears ON the affected turn when ledger drift fires (rare in new protocol). validate-run CLI is the canonical surface for per-run totals.

§ 4. Decisions I still need your call on

  • Glyph-bubble override of 0115's "never abbreviate" rule. I framed this as an evolution: full words still appear in the legend (filter row), designed bubble-icons on dense surfaces. Acceptable, or should I shape it differently?
  • Issues = red tone. Issues now use err-red (was info-blue). Distinct from Questions (info-blue), Disagreements (warn-amber), Comments (idle-grey). Concern: red can feel alarming. Want me to try a different palette mapping?
  • Comments = idle grey. Comments are advisory remarks. Idle felt right because they're the lowest-priority category. Want me to try a warmer color so they stand out more?
  • Brief card icon. Mockup uses 📄 emoji as placeholder. Want a proper SVG icon from icons.jsx (file-document exists)?
  • Belt-and-suspenders status on critique cards. Mockup keeps left-border tint (open=info, resolved=ok, ack=warn, capped=err) AND right-aligned status chip. Keep both, or rely on border alone?
  • Should category chips be clickable to filter the critique pane? 0115's uniformity invariant implies yes. Worth scoping into the new spec.
  • Run-list page, header chrome, consumption tab. Inventory those next iteration, or only fully spec the timeline+critique consolidation and let the rest follow the same governance rules?
