Deliverable 01 · Foundations · Material mode

Material 3 tokens for diagrams that share visual DNA with the dual-research dashboard.

Material mode adapts the dual-research V2 design system for diagram authoring. Every token here is either a direct read of a --md-* token from the dual-research spec, or a --ds-* diagram-skill-namespaced token derived from a --p-* palette token via a documented recipe. No literal hex values appear in component rules — the generator references tokens by name. If a situation needs a value not in the registry, the situation is wrong, not the registry.

01.0Theme model

Every Material diagram ships in two flavors — light (warm M3 cream canvas) and dark (M3 near-black canvas). The two share everything structural: viewBox, layout, type roles, spacing tokens, animation classes, connector geometry, manifest pins. They differ only in color values. Every token in the rest of this page has a dark sibling named --<token>-dark. The contract is identical to the Pixel mode — only the color palette and font family differ.

Light · default

Warm M3 cream on a polished doc page.

Vertical gradient #faf9f6 → #ece8de — the M3 --md-surface → --md-surface-dim pair. Dark categorical cards float on cream with a soft drop shadow. Light cards are --md-surface-container-lowest (#ffffff) separated by 1px --md-outline-hair strokes. Ink scale runs #04060a → #6f7480. Accent identity at #6b9cf0 (info-blue / --md-tertiary).

Files emit as <slug>.material.light.svg.

Dark · same diagram

M3 near-black canvas with lifted categorical surfaces.

Vertical gradient #0d0f12 → #08090b — the M3 --md-surface → --md-surface-dim pair (dark). Categorical surfaces lift one value step so they stay elevated. Light cards become --md-surface-container-highest (#21252b) separated by 1px rgba(255,255,255,0.10) strokes (no drop shadow). Ink scale inverts. Accent #6b9cf0 is theme-portable — it reads cleanly against either canvas.

Files emit as <slug>.material.dark.svg.

Naming convention

Every theme-dependent token has both names. Light is the canonical name; dark adds the -dark suffix. Theme-agnostic tokens (spacing, type sizes, viewBox, animation timing) have a single name and apply to both files. The convention is identical to Pixel mode for portability — code that switches modes only needs to swap the foundations file, not the token-naming pattern.

Surface gradient ids are theme-agnostic

Inside an emitted SVG, gradient ids stay stable: <linearGradient id="surfaceSql"> in both .material.light.svg and .material.dark.svg. What differs is the stop-color values inside. This lets every connector reference (fill="url(#surfaceSql)") and every card primitive author once and render correctly in either theme — the theme pass swaps stop values, not ids.

Filter ids are theme-agnostic too

The two shadow filters (cardShadow, cardShadowDark) keep the same ids across themes. The dark theme rewrites their bodies — cardShadow becomes a near-zero halo at rgba(255,255,255,0.08) (elevation via stroke-like glow), cardShadowDark becomes a deeper #000000 drop at 0.55 opacity. See §01.5.

Dual-output workflow

The skill emits two SVG files per diagram. Step 5 generates one layout; the theme pass applies each token set to produce the two files. Step 6 renders both PNGs and runs the self-review checks against each independently — see SKILL.md §5–7. A multi-diagram set pinned by theme: both in its manifest ships 2 × N SVGs per set.

What's the same as Pixel: the entire workflow contract — dual-output, theme-suffix naming, manifest authority, mixed elevation strategy (light cards lose shadow on dark canvas, dark cards deepen it). What's different from Pixel: palette (sable + sage instead of cream + indigo), type pair (Roboto Flex + Roboto Serif instead of Inter), shape scale (M3 tokens), elevation recipes (M3 6-level + tonal overlay). The behavioral spec is identical; the visual vocabulary is M3.

01.2Color · semantic palette

Every color is named by what it means, not what it looks like. Material mode draws from the dual-research V2 palette — sable, sage, info, ok, warn, err, idle — and derives every diagram-specific surface from those palette tokens via color-mix recipes. The info-blue accent is fixed; categorical card gradients are derived per-category from the V2 palette. The set manifest pins which derived surface each named service uses.

01.3Typography · roles

Type roles are named, not picked by inspection. Material mode uses the M3 default font pair — Roboto Flex (plain, variable) for chrome and body, Roboto Serif (brand) for hero text and section headlines. The diagram-skill labels need slightly more letter-spacing than the M3 web utilities because SVG-rendered labels read differently than HTML — those overrides are documented per role.

Theme portability

All keyframes are theme-agnostic — the timing, easing, and shape of every animation is identical across light and dark renders. The tick keyframe's two greens (#6fb380 and #8ac99c) both clear AA contrast against both canvases. No dark-variant keyframe needed.

01.7Cross-template consistency rules

A proposal ships 3–6 diagrams. The same Postgres must show up as --ds-surface-sql in every one — not just because identity matters, but because the set manifest enforces it. The rules below are the closed list of things the manifest pins. Cross-mode swaps (Pixel ↔ Material) are forbidden within one proposal — see manifest §07.5.

  • Service → gradient is pinned per-set. First diagram in the set declares the mapping; every subsequent diagram in the same proposal consults it. Within Material mode, the mapping uses --ds-surface-* tokens.
  • Service → icon is pinned per-set. Same logical service uses the same icon shape (e.g. cylinder for Postgres) wherever it appears.
  • Label string is pinned per-set. "Postgres" is "Postgres" everywhere — not "Cloud SQL" in one diagram and "the DB" in the next.
  • Title typography is identical. Same Roboto Serif weight, size, letter-spacing, position (centered, y=56).
  • Letter-spacing values come from --type-section and --type-conn-label. Never tighten or loosen for one diagram.
  • Margin and gap tokens are identical. A "wide" diagram doesn't get to compress --gap-card — it uses --canvas-width-wide instead.
  • Theme is pinned per-set in the manifest. Within one proposal, all diagrams render at minimum all-light or all-dark; the default theme: both ships both flavors of every figure. Per-diagram theme override is a hard error — see manifest §07.4.
  • Mode is pinned per-set. A proposal is either entirely Pixel or entirely Material. Per-diagram mode override is a hard error — see manifest §07.5.
The set manifest enforces these. A one-page YAML stub authored on the first diagram becomes part of the conversation; subsequent diagrams read it before generating. See Set manifest for the schema.
