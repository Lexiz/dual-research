Deliverable 03 · Icon library · Material mode

Seventy-eight icons hand-drawn in Material 3 outlined style, organized in nine categories, plus a fallback for everything else.

Every icon fits a 32 × 32 bounding box, uses M3 outlined-style strokes (1.8px round caps + joins), and pairs with a canonical surface gradient via the set manifest. The library mirrors Pixel mode's icon set name-for-name — same 78 icons, same 9 categories, same fallback rule — so a multi-diagram proposal can swap modes by re-rendering against this page without re-mapping services to icons. M3-style glyphs are lighter weight than Pixel's filled silhouettes; they read as "drawn" rather than "stamped."

Color via currentColor. All icon glyphs render with stroke/fill resolved to the closest color ancestor. Set the card-level color attribute and every icon inside inherits it. Use #04060a on light cards, rgba(255,255,255,0.92) on dark cards. Category-tinted icons (e.g. info-blue for sql) inherit their category color from the surface gradient.

03.0Theme × variant matrix

Each icon ships in two visual variants: on-light-card (dark stroke on cream tile) and on-dark-card (light stroke on dark tile). With the dual-theme architecture, these two variants are orthogonal to theme — there are four contexts an icon can sit in, not two. The geometry of every icon is identical across all four cells; only the stroke / fill color and tile background change.

Practical consequence: two pairs, not four variants

Although there are four theoretical contexts, only two pairs of tile/stroke colors exist:

  1. Pair A (dark glyph on light tile) — used only in "light-theme · on light card." The icon body is solid dark stroke.
  2. Pair B (light glyph on dark tile) — used in the other three contexts, with a small opacity bump for "dark-theme · on dark card."

So in practice the generator renders two glyphs per icon, not four. The cells below show pair A on the left and pair B on the right.

Monogram fallback (icon.generic-service)

When no icon matches, draw a rounded square tile (8 corner radius) with the service's first letter (or 2 initials) centered in Roboto Flex 14 / 600. The tile color comes from the service's pinned categorical surface via the manifest. Never improvise a bespoke shape.

M3 outlined stroke convention

Every Material icon glyph uses stroke-only shapes by default (not filled silhouettes). Stroke width 1.8px, round caps and joins, no inner fill except for small accent dots. This is the "outlined" variant of Material Symbols — lighter visual weight than filled icons, more sympathetic to M3's information-density bias.

03.3Fallback rule · when no icon matches

When a service doesn't fit any of the 78, use icon.generic-service — a rounded square tile with a 1–2 letter monogram in Roboto Flex 14 / 600. The tile fill comes from the service's pinned categorical surface; the monogram color uses the service's contrast ink (white on dark tile, ink-1 on light tile).

Service exampleMonogramTile
StripeSt--ds-surface-slate
SendgridSg--ds-surface-store
LaunchDarklyL--ds-surface-secure
NotionN--ds-surface-neutral
Never improvise a new glyph. If you find yourself wanting to draw a custom shape for a service that's not in the 78, stop. Use icon.generic-service with a monogram. The icon library is closed by design — every diagram in a multi-set proposal needs to use the same shape vocabulary, and ad-hoc shapes break that.
