v2 · material-flavored · 2026-05-19

A calm, dense surface — refined under Material.

The pastel palette stays. Everything around it — type, shape, elevation, state layers, motion, component anatomy — is rebuilt against the Material 3 vocabulary. Sable (Claude) is the primary color; sage (GPT) is secondary; status hues remain the only other ink. Surfaces tint with the primary so the UI feels warm on Claude pages and cool on GPT pages.

Voice & principles

§1 · identity

The system follows three rules at all times: never compete with the agent output, never compete with the terminal next to it, never hide the one number that matters. Material 3 supplies the grammar; pastel chromatics carry the identity.

visibility
Read-only is a discipline
No buttons that mutate state. Every affordance is a view filter, a tab, or a focus shift. If the user wants to act, they go to the terminal.
palette
One color per agent
Sable for Claude, sage for GPT. Status hues are the only other ink. A third agent hue gets cut.
density_medium
Density is a feature
Comfortable by default — M3 spacing gives prose room. Compact collapses one step for ops surfaces and ≤1500 viewports.
timeline
Calm transitions or none
M3 emphasized easings on layout shifts, standard on hover/focus. No bounces, no springs. Reduced-motion honored everywhere.
warning
Show why a run is slow
The disagreements panel names the contested point blocking convergence. No buried logs.
accessibility_new
Accessibility first
M3 focus rings (3px tertiary outline) on every interactive primitive. AA contrast on all text + status; semantic landmarks.
info
Adopted patterns, not branded assets. We apply Material 3 vocabulary (state layers, surface tiers, shape scale, type roles, motion easings) renamed under our own --md-* namespace. No third-party brand marks, no third-party UI imagery. The palette is ours.

Motion tokens

EMPHASIZED · LAYOUT SHIFTS
cubic-bezier(0.2, 0, 0, 1)
Used for sliding panels, modal open/close, scrubber position changes. Pairs with --md-dur-medium-1..4 (250–400 ms).
STANDARD · INTERACTION
cubic-bezier(0.2, 0, 0, 1)
Used for state changes (hover/focus/pressed). Pairs with --md-dur-short-1..4 (50–200 ms). Tactile, never floaty.

System layer

§8 · foundations · 2.6 · 2.7

Components read M3 role tokens (--md-primary, --md-surface-container-high, --md-shape-md, --md-easing-emphasized) instead of raw values. Theme, tint, and density toggles re-resolve the whole tree without touching component CSS.

COLOR ROLES
  • --md-primary → sable (Claude)
  • --md-secondary → sage (GPT)
  • --md-tertiary → live blue
  • --md-error → errored
  • Each role has a -container + --md-on-* pair
SURFACE TIERS
  • surface-dim / surface / surface-bright
  • surface-container-{lowest, low, , high, highest}
  • Plus --md-surface-1..5 derived via color-mix with primary tint
  • Body class flips tint: tint-secondary → sage
SHAPE / SPACING
  • --md-shape-xs / sm / md / lg / xl / full
  • --md-sp-0..20 on the 4dp half-step grid
  • Density flag flips: --md-pad-card, --md-gap-row, --md-row-h
MOTION / STATE
  • --md-easing-emphasized / standard
  • --md-dur-short-1..long-2
  • --md-state-hover / focus / pressed / dragged

How It Works

§18 · long-form page

Long-form documentation page (route /how). Nine sections, each anchored by a Material-flavored diagram. Body type is Roboto Flex at 16/24; section heads use Roboto Serif at the Headline Large role.

§1 · PROTOCOL OVERVIEW

The protocol at a glance

Two agents — Claude and GPT — turn a free-form brief into a single converged document by passing through five role-steered phases. Slots between phases carry artefacts; gates between phases prove convergence. The orchestrator advances only when the gate fires.

§2 · PHASE 0

Preflight & Brief

A single deterministic turn normalises the free-form brief into a canonical brief.json. No agent negotiation happens here; the preflight is mechanical. If the brief is under-specified, the preflight asks clarifying questions and re-attempts.

§3 · PHASE 1

Independent Research

Claude and GPT each retrieve sources independently. They do not share context, and each writes a structured research_*.json with citations. Strict parallelism is the discipline — accidental cross-contamination defeats the adversarial premise.

§4 · PHASE 2

Plan Negotiation

Claude proposes a plan; GPT critiques; Claude revises; cycle repeats until plan hashes match (convergence gate). If the round cap is hit without convergence, the orchestrator surfaces a deadlock alarm — the contested points are written to the run header for the operator.

§5 · PHASE 3

Drafting

One agent — chosen by the converged plan, typically Claude — writes the long-form draft section by section. The other gives in-turn feedback bounded at 120 words: structural issues, scope drift, gaps. Copy-edits are out of scope for P3; they happen in Review.

§6 · PHASE 4

Review Loop

Adversarial review at the item level. Each open item is critiqued by the non-drafter, replied to by the drafter, and either resolved or marked drift. Drift items roll into the next round. Exit gate fires when all items close — resolved or drift-converged — within the round cap.

§7 · CONVERGENCE

Disagreement & convergence

A disagreement is raised, debated, and either conceded by one side or marked drift. Drift items re-enter the next round automatically. Convergence is structural: no open items, no drift items pending — not semantic agreement.

§8 · CONSUMPTION

Cost & consumption

Context grows fastest in P1 (independent research doubles the load) and stabilises in P3 (the drafter carries; the advisor stays light). The Consumption tab on each run shows the per-phase shape so an operator can spot a cost anomaly without reading the body.

Every run lives in exactly one state. Status colors stay constant across all surfaces (status pill, timeline card outline, run-row left rule).

running

converged

All phases passed, exit gate fired, final document committed. No animation; the answer is the answer.
drift
Drift

Agent or orchestrator fault. Run halted. Operator must read the error card before any continue is possible.

No agent activity. Either between phases (queued for next) or operator-paused.
queued

Awaiting capacity. No tokens spent yet. Cost reads 0.000.

Accessibility

§22 · quality

M3 a11y defaults are stricter than v1: 3px focus ring with 2px offset, 48dp minimum hit-area on touch targets, semantic landmarks throughout. Reduced motion honored on every animation.

Focus ring 3px solid tertiary (info) with 2px offset, on every interactive primitive. Visible only via :focus-visible — never disturbs mouse users.
Hit-area Touch targets ≥ 48 × 48 dp. Icon buttons are 40px visually + 4px hidden padding ring.
Contrast All on-surface tokens hit AA at body sizes. AAA hit at headline+ sizes. Pastel statuses paired with text labels so colorblind users get the same signal.
Reduced motion prefers-reduced-motion: reduce kills every transition and animation via a single global rule.
Semantic landmarks <header>, <aside aria-label>, <main>, <section id> for each anchor. Tabs use aria-selected; switches use role="switch" aria-checked.
Skip link Visually-hidden "Skip to main" appears on first tab, jumps past the rail into the main column.

Responsiveness

§24 · NEW

Two buckets, set per user spec: wide screens (≥ 1500px) get the full layout; the common laptop (< 1500px) collapses into a denser variant. A third bucket (< 900px) drops to single-column for tablets.

BUCKET 1 · ≥ 1500px

Wide · comfortable

  • Navigation rail open (280px) with labels
  • Main column max 1440px, padding 40/48
  • Run-row: 8 columns, no wrapping
  • Agent input panes side-by-side
  • Comfortable density default
  • Headlines at Display-Small (36px)
BUCKET 2 · < 1500px

Laptop · dense

  • Rail collapses to icons (80px); labels hidden
  • Main column max 1200px, padding 32/32
  • Run-row: 5 columns with a wrapped second-line for rounds/tokens/cost
  • Agent input panes stack vertically
  • Card grids: 3-col → 2-col, 4-col → 2-col
  • Headlines drop to Headline-Large (32px)
BUCKET 3 · < 900px

Tablet · single

  • Rail hidden entirely (use top app bar overflow)
  • Single-column grid; cards stack
  • Main padding tightens to 24/24
  • Headlines at Headline-Medium (28px)
  • Compact density auto-applied
RULES OF THUMB

How to decide

  • Use M3 spacing tokens (--md-sp-*) so density can flip with one body class
  • Use grid-template-columns with breakpoint overrides, never JS-driven layout
  • Hide ornamental columns first (tokens, cost) — never the topic
  • Test at 1280px (MacBook Air), 1440px (MBP-14), 1920px (desktop) — these are the three real targets
