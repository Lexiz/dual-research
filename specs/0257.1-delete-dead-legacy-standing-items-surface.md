## 1. Current state

The legacy ledger-mode standing-items surface and its two orchestrator runners have been **unreachable from the live entry points (`run_dr_phase2` / `run_dr_phase4`) since the spec-0118 v2 rewrite.** The live surface is `deep_research.format_role_aware_standing_items` (added by 0257), rendered off the contract `LedgerEntryV2` state machine.

Dead surface, with citations:

- **`build_standing_items_section`** at [`src/dual_research/ledger/prompt.py:47`](../src/dual_research/ledger/prompt.py) — already carries the `.. deprecated:: spec 0257` note ([`src/dual_research/ledger/prompt.py:56`](../src/dual_research/ledger/prompt.py)) added by spec 0257 explicitly stating "DEAD SURFACE — flagged for deletion … Delete this function with the legacy phase2/phase4 runners; do not extend it." Re-exported from [`src/dual_research/ledger/__init__.py`](../src/dual_research/ledger/__init__.py).
- **Legacy `run_phase2`** at [`src/dual_research/orchestrator/phase2.py:76`](../src/dual_research/orchestrator/phase2.py) — its only callers of `build_standing_items_section` are at [`src/dual_research/orchestrator/phase2.py:182`](../src/dual_research/orchestrator/phase2.py) (`claude_standing`) and `:183` (`openai_standing`). The file's own comments confirm it is dead: "Spec 0118: legacy run_phase2 path no longer emits … dr_run.run_dr_phase2 is the active code path" ([`src/dual_research/orchestrator/phase2.py:145`](../src/dual_research/orchestrator/phase2.py)).
- **Legacy `run_phase4`** at [`src/dual_research/orchestrator/phase4.py:55`](../src/dual_research/orchestrator/phase4.py) — imports `build_standing_items_section as _build_si` at [`src/dual_research/orchestrator/phase4.py:178`](../src/dual_research/orchestrator/phase4.py); same dead-path comment at [`src/dual_research/orchestrator/phase4.py:220`](../src/dual_research/orchestrator/phase4.py).
- The only remaining `build_standing_items_section` references after the live path is excluded are these two legacy runners plus the deprecation note itself and orphaned tests (see §4).

**Pain:** A second, diverging standing-items renderer is exactly the wrong-layer hazard that produced 0257's reconcile-time citation bug (the spec's entire §2 cited this dead surface; the reconciler reported "clean" because the file:line locations literally exist — see the 0257 handoff "Reconcile correction"). Leaving the dead surface in place keeps that trap armed for the next ledger-prompt spec.

## 2. Target state

The dead surface is gone; the only standing-items renderer in the tree is the live `deep_research.format_role_aware_standing_items`.

- `build_standing_items_section` removed from [`src/dual_research/ledger/prompt.py`](../src/dual_research/ledger/prompt.py) and from the [`ledger/__init__.py`](../src/dual_research/ledger/__init__.py) re-export.
- Legacy `run_phase2` removed from [`src/dual_research/orchestrator/phase2.py`](../src/dual_research/orchestrator/phase2.py); legacy `run_phase4` removed from [`src/dual_research/orchestrator/phase4.py`](../src/dual_research/orchestrator/phase4.py).
- **Preserve the `Phase2Outcome` / `Phase4Outcome` dataclasses** — these live in the same legacy modules but are STILL imported by live code: [`src/dual_research/orchestrator/dr_run.py:79`](../src/dual_research/orchestrator/dr_run.py) / `:81`, [`src/dual_research/orchestrator/run.py:40`](../src/dual_research/orchestrator/run.py) / `:42`, and [`src/dual_research/orchestrator/finalize.py:8`](../src/dual_research/orchestrator/finalize.py) / `:10`. Either keep them in place (delete only the `run_phase2` / `run_phase4` function bodies and the now-unused `build_standing_items_section` import) or relocate them to a non-legacy module and rewrite the three live import sites. The dataclasses are NOT in scope for deletion; only the runners and the dead renderer are.

## 6. Risks

- **A missed live call site.** Mitigation: the deletion is guarded by `grep -rn build_standing_items_section src/` returning empty and by a clean import of the three live orchestrator modules (`run`, `dr_run`, `finalize`) — the only modules that import from the legacy files.
- **Accidentally deleting `Phase2Outcome` / `Phase4Outcome`.** Mitigation: §2 / §5 name these explicitly as preserve-only; the three live import sites are enumerated with file:line so the implementer verifies each still resolves.
- **A test file mixing dead-runner exercises with still-valid `Phase*Outcome` coverage** (`test_phase3_4_final.py`, `test_emit_final_resume.py`). Mitigation: §4 calls for surgical removal of only the `run_phase4`-dependent functions in those two files rather than whole-file deletion.
- **Revert plan:** pure deletion with no migration and no state — if anything breaks, revert the commit; nothing to unwind.
