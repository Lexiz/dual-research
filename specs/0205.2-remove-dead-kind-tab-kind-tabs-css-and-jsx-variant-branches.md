# Spec 0205.2 — Refactor: remove dead `.kind-tab` / `.kind-tabs` CSS + shared.jsx variant branches

> **Type:** refactoring  |  **Complexity:** S  |  **Depends on:** 0205
> **Bump:** PATCH — dead-code removal, no behavior change
> **Evidence:** spec 0205 §3.4 authorised removal IFF nothing else depended on the legacy `kind-tab` / `kind-tabs` surfaces — *"Remove the now-unused `variant=\"kind-tabs\"` and `variant=\"kind\"` branches in `shared.jsx` IFF nothing else depends on them (grep before deletion; if still used elsewhere, leave them and only stop emitting from this call site)."* Grep confirmed no other call sites in `src/dual_research/ui/static/`; the spec-0205 implementer left the rules in place to keep the bugfix PR scoped. The handoff at `handoffs/2026-05-24-spec-0205-fix-p4-critique-card-five-visual-regressions.md:49` is the explicit deferral.

## 1. Current state

Spec 0205 Bug 4 replaced the Bar 2 kind filter row (P4 critique pane) from `<TabGroup variant="kind-tabs">` + four `<Tab variant="kind">` segmented buttons to four `<Chip>` instances inside a new `.kind-chip-row` wrapper. The legacy `.kind-tab` / `.kind-tabs` JSX branches and CSS rules survived in four locations:

- **JSX `TabGroup` branch** at `src/dual_research/ui/static/shared.jsx:1061` and `:1066` — the `variant === 'kind-tabs'` arm of the `variantClass` / `baseClass` ternaries (returns `null` and `'kind-tabs'` respectively).
- **JSX `Tab` branch** at `src/dual_research/ui/static/shared.jsx:1103`–`:1112` — the `variant === 'kind'` arm that emits a `.kind-tab` button with `is-active` className, `.ct` count span, and a no-op `Mdi` icon slot.
- **CSS in `src/dual_research/ui/static/components.css:2305`–`:2356`** — the `.kind-tabs` / `.kind-tab` rule block (display flex, hover layer, active background, zero-state opacity, focus ring, `.ct` count badge with per-tone variants, narrow-mode label collapse at the `@media` rule near `:1099`).
- **CSS in `design-system/assets/styles/composed-components.css:727`–`:830`** — the canonical DS copy of the same rules, including the spec-0205 header comment at `:727` that prose-justifies why the rules survive ("legacy `.kind-tab` segmented control to the shared Chip primitive… `.kind-tab` rules below stay for any legacy surface that hasn't migrated").

Plus the DS prose hedge at `design-system/SPEC.md:525` ("The legacy `.kind-tab` / `.kind-tabs` CSS rules survive for any pre-0205 surface that hasn't migrated") that documents the legacy survival.

**Why this is dead code, not deprecated-but-live:** spec 0205 §3.4 instructed the implementer to grep before deletion. The grep happened and surfaced zero other call sites in `src/dual_research/ui/static/`; the only consumer was the one call site spec 0205 migrated. The legacy survives only because the implementer scoped the bugfix PR to the regression bundle. The "pre-0205 surface that hasn't migrated" the prose at `composed-components.css:730` references doesn't exist — there is no such surface anywhere in the live app. The hedge is preemptive documentation against a hypothetical, not coverage of a real consumer.

**Pain points:**

- **DS prose lies.** `design-system/SPEC.md:525` claims a survival reason ("any pre-0205 surface that hasn't migrated") that does not exist. A spec author reading the DS today is told the rules cover a live surface; they don't.
- **CSS bytes shipped to browser.** ~50 lines in `src/dual_research/ui/static/components.css` and a mirror copy in the DS file ship to every viewer of every page, unread.
- **JSX branches confuse future readers.** `shared.jsx`'s `TabGroup` and `Tab` carry six variants today (`undefined`, `'line'`, `'solid'`, `'md-tabs'`, `'tab-group-solid'`, `'phase-tabs'`, `'kind-tabs'` on TabGroup; `'primary'`, `'solid'`, `'kind'`, `'phase'`, `'chrome'` on Tab). Two of those are dead. The `variant: 'kind-tabs'` and `variant: 'kind'` comment at `src/dual_research/ui/static/shared.jsx:1048` and `:1050` also lies — it documents the variant as supported.

## 2. Target state

Four deletions + one prose hedge removal, all in a single PR:

- `src/dual_research/ui/static/shared.jsx:1055`–`:1073` — `TabGroup` keeps every variant arm EXCEPT the `'kind-tabs'` arms at `:1061` and `:1066`. Update the comment at `:1048` to drop `'kind-tabs'` from the documented variants list.
- `src/dual_research/ui/static/shared.jsx:1074`–`:1113` — `Tab` keeps every variant branch EXCEPT the `variant === 'kind'` block at `:1103`–`:1112`. Update the comment at `:1050` to drop `'kind' (kind-tab)` from the documented variants list.
- `src/dual_research/ui/static/components.css:2305`–`:2356` (the `.kind-tabs` / `.kind-tab` rule block) — delete in full, including the section header comment at `:2305`. Also delete the narrow-mode label-collapse rules near `:1099` (the `.kind-tab` selectors inside `@media` blocks) and the comment block at `:1058`–`:1062` that explains why they survive ("Spec 0205 Bug 4 — `.kind-tabs`… `.kind-tab` markup for any pre-0205 surface that hasn't migrated").
- `design-system/assets/styles/composed-components.css:727`–`:830` — delete the entire `.kind-tabs` / `.kind-tab` block including the header comment at `:727`–`:740` and any narrow-mode `@media` rules.

After the deletions, `shared.jsx`'s `TabGroup` supports five variants and `Tab` supports four; `components.css` and `composed-components.css` each drop ~60 lines of unread CSS; DS prose stops claiming a survival reason that doesn't exist.

## 7. Risks

- **Hidden live consumer.** If some pre-0205 surface I missed in the grep still emits `<TabGroup variant="kind-tabs">` or `<Tab variant="kind">`, deleting the variants breaks that surface silently (the JSX would render with default styling). Mitigation: §3's Step 1 + Step 2 grep is the verification; if the grep surfaces ANY call site, halt and re-scope. Additionally, the spec-0205 static-pattern test at `tests/test_spec_0205_critique_card.py:1` already pins `.kind-chip-row` presence, so if the Bar 2 row regresses to the legacy shape, the test fails.
- **DS prose drift.** Stripping the survival sentence at `design-system/SPEC.md:525` leaves the §4.8 paragraph cleaner but assumes no other DS section refers to "kind-tab" or "kind-tabs". Mitigation: grep `design-system/SPEC.md` for `kind-tab` before commit; surface any other reference for one-line strip in the same commit.
- **Performance regression from CSS deletion.** Highly unlikely — deleting unread rules can only make the page faster, not slower. Listed for completeness.
- **Reviewer confusion about why the deletion is "safe now but wasn't at spec 0205 time".** Mitigation: this spec body + the explicit deferral entry at `handoffs/2026-05-24-spec-0205-fix-p4-critique-card-five-visual-regressions.md:49` document the rationale. The spec-0205-time risk ("future surface that hasn't migrated") was a hypothetical that hasn't materialized; the cleanup is overdue, not premature.
