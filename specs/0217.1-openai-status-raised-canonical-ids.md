# Spec 0217.1 — Fix: tighten STATUS.RAISED_THIS_TURN prompt contract to canonical IDs only

> **Type:** bug  |  **Severity:** P2  |  **Affects:** phase-2 / phase-4 ledger reconstruction via STATUS-pass (continuation of spec 0217)
> **Bump:** PATCH — prompt-contract fix

Captured verbatim in the spec-0217 hermetic fixture at [tests/fixtures/spec_0217/phase2/round-01-openai.md:81](tests/fixtures/spec_0217/phase2/round-01-openai.md:81). Deferred in the spec 0217 handoff at [handoffs/2026-05-25-spec-0217-ledger-status-block-authoritative-for-closures.md:171](handoffs/2026-05-25-spec-0217-ledger-status-block-authoritative-for-closures.md:171).

## 1. Reproduction

**Environment:** dual-research prod tier, phase-2 negotiation. Any session where one of the agents (here: openai) populates `STATUS.RAISED_THIS_TURN` with descriptive strings instead of canonical IDs.

**Steps:**

1. Run a phase-2 negotiation that surfaces ≥ 1 disagreement raised by openai.
2. Observe round-1-openai's `## Status` block — under the current prompt template, the agent may emit something like:
   ```
   RAISED_THIS_TURN: [
     "disagreement: Go #1 vs C# #1",
     "question: evidence threshold for Go AI-coding-agent advantage",
     ...
   ]
   ```
   (exact text reproduced at [tests/fixtures/spec_0217/phase2/round-01-openai.md:81-89](tests/fixtures/spec_0217/phase2/round-01-openai.md:81)).
3. In subsequent rounds openai correctly emits `RESOLVED_THIS_TURN: [D-plan-g-01, ...]` and `WITHDRAWN_THIS_TURN: [Q-plan-g-01]` using canonical IDs.

**Expected:** Round-1 STATUS arrays contain only canonical IDs (`D-plan-g-01..05`, `Q-plan-g-01..02`). Spec 0217's STATUS-pass in [src/dual_research/ui/disagreements.py:587-610](src/dual_research/ui/disagreements.py:587) seeds entries for those IDs in round 1; later `RESOLVED_THIS_TURN` flips them to resolved; openai's side of the negotiation appears in the reconstructed ledger.

**Actual:** Round-1 STATUS array contains descriptive strings. The STATUS-pass at [src/dual_research/ui/disagreements.py:587](src/dual_research/ui/disagreements.py:587) and the parallel pass in [src/dual_research/ui/questions.py](src/dual_research/ui/questions.py) cannot canonicalize those strings into `D-…` / `Q-…` IDs, so `raised_ever` never sees the items. Later canonical-ID closures from openai (`D-plan-g-01..05`, `Q-plan-g-02` RESOLVED; `Q-plan-g-01` WITHDRAWN) are correctly dropped by the §8 spurious-ID mitigation at [src/dual_research/ui/disagreements.py:602-604](src/dual_research/ui/disagreements.py:602) — but the ledger loses visibility into the entire openai-side negotiation. Spec 0217's handoff calls this out explicitly at [handoffs/2026-05-25-spec-0217-ledger-status-block-authoritative-for-closures.md:171](handoffs/2026-05-25-spec-0217-ledger-status-block-authoritative-for-closures.md:171).

## 2. Root cause hypothesis

The phase-2 round-1 prompt template at [src/dual_research/protocol/prompts.py:1568-1573](src/dual_research/protocol/prompts.py:1568) prints the STATUS footer with a permissive placeholder:

```
RAISED_THIS_TURN: [list of IDs the orchestrator will assign]
```

That phrasing leaves the field open to interpretation — agents that are unsure which IDs are "real" sometimes substitute prose descriptions for IDs (the smoking-gun session shows openai doing exactly that). The phase-2 round-N template at [src/dual_research/protocol/prompts.py:1786](src/dual_research/protocol/prompts.py:1786) and the phase-4 template at [src/dual_research/protocol/prompts.py:2041](src/dual_research/protocol/prompts.py:2041) use the even-more-ambiguous `RAISED_THIS_TURN: [...]`, and the shared `_status_footer_for_phase` helper at [src/dual_research/protocol/prompts.py:1416](src/dual_research/protocol/prompts.py:1416) emits the same `[...]` placeholder for all phases that reference it.

The reconstructor's STATUS-pass in spec 0217 already treats canonical-ID arrays as authoritative; the protocol contract just doesn't say loudly enough that "canonical ID" is what the array must contain. Tightening the prompt is the structurally correct fix — the canonical-channel guarantee should live at the contract layer, not be salvaged by post-hoc heuristics in the reconstructor.

The handoff explicitly recommends this path: "Path (a) is the structurally correct fix — STATUS arrays should be ID-only by contract" ([handoffs/2026-05-25-spec-0217-ledger-status-block-authoritative-for-closures.md:188](handoffs/2026-05-25-spec-0217-ledger-status-block-authoritative-for-closures.md:188)).

## 3. Fix

Tighten the STATUS-block contract in [src/dual_research/protocol/prompts.py](src/dual_research/protocol/prompts.py) so every action array (`RAISED_THIS_TURN`, `ADDRESSED_THIS_TURN`, `RESOLVED_THIS_TURN`, `ACKNOWLEDGED_THIS_TURN`, `WITHDRAWN_THIS_TURN`) is explicitly documented as a list of canonical IDs only — never descriptive prose, never quoted strings, never multi-line natural-language descriptions.

### 3.1 — Update placeholder text in all three phase-2/phase-4 footers

Replace the loose placeholders:

- Line 1569: `RAISED_THIS_TURN: [list of IDs the orchestrator will assign]` → `RAISED_THIS_TURN: [<canonical-id>, ...]  # e.g. [D-plan-c-01, Q-plan-c-02] — IDs only, never descriptive prose`
- Line 1786: `RAISED_THIS_TURN: [...]` → same canonical-ID-only template as 3.1.
- Line 2041: same fix.

Mirror the canonical-ID-only constraint on every action array in the same blocks (`ADDRESSED_THIS_TURN`, `RESOLVED_THIS_TURN`, `ACKNOWLEDGED_THIS_TURN`, `WITHDRAWN_THIS_TURN`).

### 3.2 — Update the shared `_status_footer_for_phase` helper

In [src/dual_research/protocol/prompts.py:1408-1428](src/dual_research/protocol/prompts.py:1408), replace the `[...]` placeholders in the `base` list with the canonical-ID-only template from §3.1, so all phases that pull the footer via this helper inherit the tightened contract.

### 3.3 — Add a one-paragraph "STATUS array contract" callout

Inline above the footer template in every prompt that emits one (round-1 and round-N for both phase 2 and phase 4), add a short explicit-rule paragraph:

> The STATUS action arrays carry **canonical IDs only** — `D-<slug>` for disagreements and `Q-<slug>` for questions, exactly as they appear in the `### RAISE` / `### ADDRESS` / `### RESOLVE` blocks elsewhere in this turn. Do NOT substitute descriptive prose, quoted strings, or multi-line natural-language descriptions for IDs. The orchestrator parses these arrays as the canonical ledger-op channel; non-ID entries are silently dropped.

Round 1 keeps the parenthetical hint that the orchestrator assigns IDs, but as a separate clarification on the surrounding prose — not as a substitute placeholder inside the array.

### 3.4 — Do NOT modify the reconstructor

Spec 0217's STATUS-pass at [src/dual_research/ui/disagreements.py:587-610](src/dual_research/ui/disagreements.py:587) and the parallel pass in [src/dual_research/ui/questions.py](src/dual_research/ui/questions.py) handle canonical IDs correctly today. Adding heuristics to canonicalize descriptive strings (option (b) from the handoff) would re-fragment the source of truth in the same way `### RESOLVE <id>` parsing would have (spec 0217 §3.4). The fix lives at the contract layer.

### 3.5 — Reconstructor behavior unchanged for malformed inputs

Sessions whose turns still emit descriptive-string arrays (legacy runs predating this fix, or any agent drift) continue to be handled correctly by the existing §8 spurious-ID drop at [src/dual_research/ui/disagreements.py:602-604](src/dual_research/ui/disagreements.py:602): canonicalize-or-drop, never crash. No reconstructor changes required.

## 4. User stories & acceptance criteria

The protocol prompts are backend strings, not UI surfaces. The validator nonetheless treats any `src/dual_research/ui/` citation in the body as UI-touching; the user stories and BDD scenarios below describe the observable contract of the rendered prompt. The §5 regression-prevention test remains the load-bearing gate.

### 4.1 — User stories

> As a `dev`, I want the STATUS-block contract documented in the prompt template to say "canonical IDs only" explicitly, so that agents stop substituting descriptive-string arrays for ID arrays and the ledger captures both sides of every phase-2 / phase-4 negotiation.

> As a `dev`, I want the constraint to live in the shared `_status_footer_for_phase` helper, so that phase-0 / phase-2 / phase-4 prompts inherit one canonical wording and a future phase doesn't drift back into ambiguity.

### 4.2 — Acceptance scenarios (BDD)

> **Scenario 1:** phase-2 round-1 prompt restates the canonical-ID-only rule
> GIVEN a rendered phase-2 round-1 prompt produced by the public prompt helper in [src/dual_research/protocol/prompts.py](src/dual_research/protocol/prompts.py)
> WHEN the rendered string is searched for the §3.3 callout wording (e.g. the substring `IDs only` adjacent to the STATUS footer)
> THEN the substring is present, and the bracketed placeholder around `RAISED_THIS_TURN` no longer matches the pre-fix `[list of IDs the orchestrator will assign]` exact phrasing

> **Scenario 2:** phase-2 round-N + phase-4 prompts inherit the constraint via the shared helper
> GIVEN a rendered phase-2 round-N prompt and a rendered phase-4 prompt — both pull from `_status_footer_for_phase` at [src/dual_research/protocol/prompts.py:1408](src/dual_research/protocol/prompts.py:1408)
> WHEN each rendered string is searched for the same §3.3 callout wording
> THEN both contain the substring, and neither contains the bare `RAISED_THIS_TURN: [...]` ellipsis-only placeholder that the pre-fix templates emitted

## 6. Blast radius

The fix only changes prompt text. Specifically:

- **Agent behavior** — agents that already emit canonical IDs (`D-plan-c-01`, etc.) see a stricter restatement of the rule they already follow. Agents that previously emitted descriptive strings now have an explicit instruction not to. No agent-tool / function-call schema changes.
- **Reconstructor** — unchanged. The STATUS-pass at [src/dual_research/ui/disagreements.py:587-610](src/dual_research/ui/disagreements.py:587) parses canonical IDs; the §8 spurious-ID drop handles anything else exactly as today.
- **Existing tests** — spec 0217's 7-test suite at `tests/test_spec_0217_ledger_status_authoritative.py` continues to pass: the fixtures it uses already contain canonical IDs, so the tightened prompt doesn't shift any assertion. The smoking-gun-replay test (Test 5.7) still asserts the claude-side 5 D + 2 Q items close at round 3 — openai-side items remain out of the ledger because the fixture under `tests/fixtures/spec_0217/phase2/round-01-openai.md` is captured **as-is** from the pre-fix run. That fixture is not regenerated by this spec.
- **Orchestrator / ledger / UI** — unaffected.

The change is monotonic in agent-behavior cleanliness: agents that emit canonical IDs stay correct; agents that drifted to prose are now explicitly told not to.

## 7. Out of scope

- **Reconstructor-side descriptive-string canonicalization** (option (b) from the spec 0217 handoff). Explicitly NOT pursued — see §3.4. The handoff itself notes option (a) is the structurally correct fix.
- **Regenerating the spec 0217 fixture** at [tests/fixtures/spec_0217/phase2/round-01-openai.md](tests/fixtures/spec_0217/phase2/round-01-openai.md) with canonical-ID arrays. The fixture is hermetic and load-bearing for spec 0217's Test 5.7; rewriting it would muddy what that test asserts. Future sessions will produce canonical-ID arrays naturally once this spec lands.
- **A protocol-violation event when the parser sees a non-ID entry.** Could be added later as defense-in-depth; not blocking. If the tightened prompt fails to fix the drift in practice, a follow-up spec can wire a `ProtocolViolation` event into the STATUS-pass at [src/dual_research/ui/disagreements.py:602-604](src/dual_research/ui/disagreements.py:602) (today it silently drops).
- **Phase-0 STATUS arrays.** The same loose placeholder appears at [src/dual_research/protocol/prompts.py:1416](src/dual_research/protocol/prompts.py:1416) via `_status_footer_for_phase`. §3.2 covers the helper, so phase 0 inherits the fix automatically — but no new phase-0 test is added in this spec.

## 8. Risks

- **Risk: An agent's prompt-following degrades enough that the tightened wording is ignored anyway.** Mitigation: the reconstructor's §8 spurious-ID drop at [src/dual_research/ui/disagreements.py:602-604](src/dual_research/ui/disagreements.py:602) is a safety net; descriptive-string arrays continue to be dropped silently, never crash. The headline regression (claude-side items in spec 0217) does not regress because that path uses canonical IDs.
- **Risk: Tightened wording causes a behavior shift in existing agents that subtly changes other STATUS-block usage.** Mitigation: change is purely additive instruction text — no removed phrasing, no schema change. Spec 0217's full 7-test suite plus the broader test runner (1962 passing as of v1.44.22) acts as a regression gate.
- **Risk: Token-budget cost of the additional paragraph.** Trivial — one short paragraph per prompt template, three sites total. Negligible vs. the existing prompt size.
