# Spec 0257.2 — Fix: raiser self-ADDRESSes its own already-addressed items

> **Type:** bug  |  **Severity:** P2  |  **Affects:** v1.66.0 (spec 0257's role-aware standing-items surface), phase-2 negotiation
> **Bump:** PATCH — prompt-text-only steering fix, no contract change
> **Evidence:** live run `20260530-205144-spec-0257-validation` — 5× `raiser_self_address`, all phase 2 / round 3 / agent `claude` / `from_state: addressed` (items `D-plan-c-01`..`04`, `Q-plan-c-01`).

---

## 1. Reproduction

**Environment:** phase-2 plan negotiation, prod-tier models, live entry point `run_dr_phase2` → `_drive_interaction_phase` → `dr_run._format_standing_items` ([`src/dual_research/orchestrator/dr_run.py:609`](../src/dual_research/orchestrator/dr_run.py)) → `format_role_aware_standing_items` ([`src/dual_research/orchestrator/deep_research.py:215`](../src/dual_research/orchestrator/deep_research.py)).

**Steps:**
1. Run phase-2 negotiation to the point where the raiser's own items have been ADDRESSed by the other agent (state flips `open → addressed`), so they render under group 3 — "Raised by you — ADDRESSED, ready for you to ratify" ([`src/dual_research/orchestrator/deep_research.py:266`](../src/dual_research/orchestrator/deep_research.py)).
2. Observe the raiser's next turn (round 3 in the evidence run).

**Expected:** the raiser ratifies its addressed items via `### RESOLVE` / `### ACKNOWLEDGE` / `### WITHDRAW` (or counter-argues, flipping the item back to `open`) — all legal `addressed → *` transitions per [`src/dual_research/contract/lifecycle.py:57`](../src/dual_research/contract/lifecycle.py) (`State.ADDRESSED → {RESOLVED, OPEN, WITHDRAWN, ACKNOWLEDGED}`).

**Actual:** the raiser emits `### ADDRESS <id>` on its OWN already-addressed items — the `raiser_self_address` violation (spec 0216 observability). In the evidence run this fired 5× (phase 2, round 3, agent `claude`, `from_state: addressed`: `D-plan-c-01`..`04`, `Q-plan-c-01`). The ops were **dropped and did NOT block convergence** — all three phases still reached `via_genuine_resolution`. This is a non-blocking steering gap, not a contract break.

Spec 0257 otherwise succeeded on this run: all three phases converged `via_genuine_resolution` (up from `via_ghost_cap` / `via_artifact_promotion`), and 2 of the 3 dominant phase-2 violation classes were eliminated (`resolve_from_non_addressed` 24→0, `agreed_with_open_addressed_items` 20→0). `raiser_self_address` is the lone residual.

## 2. Root cause hypothesis

The group-3 standing-items instruction added by spec 0257 — `_RAISER_ADDRESSED_INSTRUCTION` at [`src/dual_research/orchestrator/deep_research.py:176`](../src/dual_research/orchestrator/deep_research.py) — lists the ratify ops (RESOLVE / ACKNOWLEDGE / counter-argue) but **never prohibits ADDRESS**:

```python
_RAISER_ADDRESSED_INSTRUCTION = (
    "You raised these and the other agent has now ADDRESSed them — they are "
    "ready for you to ratify. You may `### RESOLVE <id>` (you accept the "
    "response), `### ACKNOWLEDGE <id>` (the disagreement is irreconcilable), "
    "or counter-argue (which flips the item back to open with your "
    "rationale)."
)
```

By contrast the group-2 constant `_RAISER_OPEN_INSTRUCTION` at [`src/dual_research/orchestrator/deep_research.py:167`](../src/dual_research/orchestrator/deep_research.py) **does** carry the prohibition explicitly:

```python
"... Do NOT emit `### ADDRESS <id>` on your own item (that is "
"`raiser_self_address`), and do NOT emit `### RESOLVE <id>` while the "
"item is still open ..."
```

When the raiser's item flips `open → addressed`, the rendering moves it from group 2 to group 3 (`raiser_open` → `raiser_addressed`, partitioned at [`src/dual_research/orchestrator/deep_research.py:242-247`](../src/dual_research/orchestrator/deep_research.py)). The item thereby **loses the no-self-address prohibition** that group 2 carried — so the raiser reaches for `### ADDRESS` again. The prohibition is exactly the steering group 3 is missing.

## 3. Fix

**Prompt-text-only change on the live surface.** Add the no-self-address prohibition to `_RAISER_ADDRESSED_INSTRUCTION` ([`src/dual_research/orchestrator/deep_research.py:176`](../src/dual_research/orchestrator/deep_research.py)), mirroring the group-2 wording for consistency. State explicitly that:

- to act on your own ADDRESSED item the legal moves are `### RESOLVE` / `### ACKNOWLEDGE` / `### WITHDRAW` (or counter-argue, which flips it back to `open`) — all legal `addressed → *` edges per [`lifecycle.py:57`](../src/dual_research/contract/lifecycle.py);
- emitting `### ADDRESS <id>` on your own item is `raiser_self_address` and will be dropped.

Diff sketch:

```python
_RAISER_ADDRESSED_INSTRUCTION = (
    "You raised these and the other agent has now ADDRESSed them — they are "
    "ready for you to ratify. You may `### RESOLVE <id>` (you accept the "
    "response), `### ACKNOWLEDGE <id>` (the disagreement is irreconcilable), "
    "`### WITHDRAW <id>` (you drop the item), or counter-argue (which flips "
    "the item back to open with your rationale). Do NOT emit `### ADDRESS "
    "<id>` on your own item — that is `raiser_self_address` and will be "
    "dropped; the item is already addressed, so ratify it instead."
)
```

`WITHDRAW` is surfaced here because it is already a legal `addressed → withdrawn` transition ([`lifecycle.py:60`](../src/dual_research/contract/lifecycle.py)); naming it does not widen the contract. No code path, partition logic, verifier invariant, lifecycle edge, or event type changes — only the rendered instruction string.

## 8. Risks

- **Wording drift between group 2 and group 3.** Mitigation: the fix mirrors the existing group-2 phrasing (`` Do NOT emit `### ADDRESS <id>` on your own item ... `raiser_self_address` ``) so the two groups speak with one voice; the §5 antipodal test locks the prohibition's presence in group 3.
- **Over-steering the raiser away from a legitimate counter-argue.** Mitigation: the instruction keeps counter-argue (→ `open`) explicitly listed alongside the ratify ops; only `### ADDRESS` is prohibited.
- **Revert plan:** single-constant string change with no state or migration — if a live re-run shows a regression, revert the commit; nothing to unwind.
